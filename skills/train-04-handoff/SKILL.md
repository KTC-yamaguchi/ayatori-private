# Step 04（セッションA末尾）: 引き継ぎブリーフィング

**位置づけ**: セッションA（📚+🙎‍♂️）の最後にファシリテーターが行う送り出し。ここから先の
ステップ4〜6 は**素の本体パイプライン（B群）を訓練中のコンサルタントが別の会話で直接実行**する（train 固有スキルは無い＝
`/ayatori-question` → `/ayatori-requirements` → `/ayatori-design` → `/ayatori-screens` を訓練中のコンサルタントが自分で打つ）。
B群にはファシリテーターが横につけないため、必要な地図と観点をここで全部渡して送り出す。

## 前提

- ステップ3完了（`session.json.step3_completed_at` が set）。`understanding-notes.md` に両シート＋目標整理シートが確定済み
  （**オート記入で G1・G2 が空欄のまま進んだ回は、空欄のままで確定済みとして扱う**＝本ステップで書き直しを促さない。
  §phase「目標整理シートの空欄」）。

## 手順

1. **現在地の更新＋ハンドブックを最終版で開く（実操作・必須）** — 次を**実際に実行してから**進む:
   - a. `artifacts/{app_name}/session.json` を Read → `current_step` を **`4`**（＝これから B群のパイプライン入力）に
        更新 → Write back。
   - b. `skills/train-handbook/SKILL.md` の手順Aで `active_form = null`（どのフォームも「← いまここ」にしない・
        行程表と3つの基準を読む段階）で**再生成（guide.html を Write）**。続けて**手順A4 の open 判定に従う**（初回のみ
        open・2回目以降は Write のみ。可否は `handbook_opened` が判定）。手順一覧は「ステップ4 パイプライン入力」が
        「◀ いまここ」になる。以降 B群の間はこのハンドブックが相棒（静的）になる（開いたタブに戻れば最新・閉じていたら開き直す）。

> **原則: 行程表・3つの基準・注意書きは既にハンドブックに載っている**（`🗺️ 全手順・現在地`／`🧵 パイプライン操作`／
> `🔍 人間ゲートの基準`）。チャットで**同じ内容を列挙し直さない**（読みにくくなるだけ）。📚 は「**今ここ／次の1手／
> どこを見ればよいか**」だけを短く述べ、詳細はハンドブックの章名を**指す**。ハンドブックが正本。

2. **引き継ぎの案内（この 4 点は 1 発話にまとめる・200 字以内）** — 渡す 4 点（今ここ／注意の在り処／レビューの
   見方／相談窓口）は、上の原則どおり**章名を指すだけ**に削れば 1 発話に収まる（下記骨子で実測 180 字）。
   **4 点を小分けにして応答を待ちながら刻まない**（列挙し直すと 400 字超に膨れるが、それは原則違反による膨張で
   あって 4 点が重いからではない）:
   - ここで言う「1 発話にまとめる」の対象は**この 4 点だけ**。200 字上限は phase の規約どおり**発話ごと**に効くので、
     **目的の違う案内を別発話で足すのは妨げない**（各発話が 200 字以内で、1 発話につき頼むことが 1 つであればよい）。
   > 「ハンドブックの『🗺️ 全手順・現在地』を見てください。今は**『パイプライン入力＋レビュー』**が『◀ いまここ』です。
   >  この後の順序と注意書き（Confluence 保存・Slack 通知・Figma 書き出しは**スキップでOK** 等）は
   >  『🧵 パイプライン操作』、レビューでの見方は『🔍 人間ゲートの基準』にあります。迷ったらこの会話に戻って
   >  オーナーに聞いて構いません（閉じてしまったら新しい会話で `/ayatori-train`）。」
   - **行程表・3つの基準・細かい注意（ゲート21が終了点／エスカレーション版で『最初からやり直す・却下』は選ばない 等）の
     本文をチャットに書き出さない**（いずれもハンドブックに実在する）。チャットに残すのは「今ここ」と「見る場所」だけ。
   - **チャットで実質的に渡すのは「スキップでOK」の判断だけ**（Confluence / Slack / Figma）。これはハンドブックに
     書かれていないため、章名を指すだけでは伝わらない。逆に言えば、他の 3 点は指すだけでよい。
   - レビューは**「見方」だけを指し、「答え」（何が混入・不足か、AI が何を足したか等の具体項目）は渡さない**
     （phase「人間ゲートでは見方だけ渡す・具体項目を名指ししない」）。
   - **次に打つコマンド（`/ayatori-question`）はここでは出さない** — 案内の途中でコマンドを見せると、学習者が
     残りの説明（見る場所・スキップ判断）を読まずに新しい会話へ移ってしまう。提示は移行ゲート通過後の
     送り出し（「完了後」）に一本化する。復帰手段の
     `/ayatori-train` は「次の一手」ではないので上記骨子に含めてよい。
   - この案内後も本セッション（A）はオーナー呼び出し（`ayatori-train-persona` の `hearing_reply`）を
     受け付ける。聞き戻しがあれば `dialogue-log.md` に追記する（ステップ7の材料として一続きにする）。
     その際、オーナーの応答で新しい事実が確定したターンには phase「未反映の注意喚起」の定型一文を同様に添える
     （相談モードだけでなく、本セッション（A）内の聞き戻しにも適用する）。
     **ただし聞き戻しへの応答を開始するのは、下記の予告＋境界マーカー追記を済ませた後にする**
     （マーカー前の発話を作らない）。
   - あわせて**追加インプットの予告**も渡す（聞き戻しで得た新情報は要件文書に自動で入らないため、
     反映漏れを本人が防げるようにする）:
     > 「ひとつ注意です。聞き戻しで**新しく決まったこと**は、AYATORI の要件文書には**自動では入りません**。
     >  反映するなら、**ご自身で AYATORI に追加インプット**するのを忘れずに（やり方はハンドブックの
     >  『これまでの内容をパイプラインへ入力する際の操作手順』の注意書きにも載せてあります）。」
   - この予告を渡したら、**この時点で** `dialogue-log.md` の末尾に**境界マーカー**を1行追記する
     （以降の聞き戻し — 本セッション（A）内のものを含む — がステップ7で「引き継ぎ後」と判別されるように、
     聞き戻しの受付開始**前**に書く）。**既に同一マーカー行が存在する場合は追記しない**（冪等・重複させない）。
     書式は次の1行を逐語で使う:
     ```
     --- Step 4 引き継ぎブリーフィング済み（以降のオーナー発話は引き継ぎ後の聞き戻し） ---
     ```

3. **引き継ぎ済みの印 → 移行ゲート（AskUserQuestion）** — 上記の案内を渡したら、**ゲートを出す前に**
   `session.json` を Read → `step4_briefed_at` を追記 → Write back する（`current_step` は手順1で `4` に設定済み。
   B群は素のパイプラインで進むため以降 train 側の `current_step` は進めない。B群内の進行判定は次回 `/ayatori-train`
   起動時に `pipeline-state.json` の承認時刻から行う）。
   - **印は「引き継ぎを渡し終えた」の記録であり、ゲートの回答には関与しない**（schema の宣言どおり「渡した時刻」）。
     ゲートを出せている＝案内は届いているので、この時点で立てる。「続ける」が選ばれても・回答が来ないまま学習者が
     新しい会話へ移っても、印は立っており**次回起動で本ステップをやり直しにならない**（再開判定は phase Preamble）。
   続けて phase「ステップ移行ゲート」に従い**共通2択**を出す
   （**「B群」等の内部用語は出さない**・phase「内部用語を訓練中のコンサルタントに出さない」を厳守）:
   - 「次のステップに進む」（内部的には B群だが、訓練中のコンサルタントには「新しい会話で `/ayatori-question` を実行して進める」と伝える）
   - 「もう少し続ける（今のステップを続ける）」
   - 「進む」で下記完了処理へ。「続ける」なら本セッションに留まる。
   - （「オーナーに聞き戻したい」等の申し出があれば、そのとき `ayatori-train-persona`（`hearing_reply`）で応答し
     `dialogue-log.md` に追記する。選択肢には出さない。）

## 完了後

- `dialogue-log.md` に境界マーカーがまだ無ければ、手順2と同じ書式で末尾に1行追記する（通常は手順2で
  追記済みのため何もしない。冪等 — 同一マーカー行が既にあれば追記しない）。
- `step4_briefed_at` は手順3 でゲート提示の直前に記録済み（ここでは書かない）。
- 表示: 「引き継ぎブリーフィングは以上です。新しい会話で `/ayatori-question`（アプリ名 `{app_name}`）から
  始めてください。迷ったら `/ayatori-train` に戻ってきてください。」
