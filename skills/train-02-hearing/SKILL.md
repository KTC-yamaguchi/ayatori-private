# Step 02: ヒアリング

**磨く力**: ヒアリング力（問う）

**役割**: 📚AIファシリテーターは正解ファイルを一切開かない。訓練中のコンサルタントが自分で問いを組み立て、
オーナー役 subagent（`ayatori-train-persona`）から引き出す。ファシリテーターは記録係・進行係に徹し、
○×判定・採点をしない（答え合わせはステップ7）。

## 前提

- ステップ1（イントロダクション）完了。`session.json.scenario_id` が確定済み。
- `artifacts/{app_name}/dialogue-log.md` にステップ1のイントロ（オーナーの最初の発言）が記録済み
  （ステップ1 手順3b が記録する。未記録なら本ステップ冒頭で `ayatori-train-persona` を `scenario_id`（session.json）付きで `mode: "intro"` で
  再起動して intro_text を取得し直し、追記してから始める——main は intro_text を保持しないため subagent 経由でしか復元できない）。

## 手順

1. **現在地の更新＋ハンドブックの再生成（実操作・必須。narration で済ませない）** — 次を**実際に実行してから**進む:
   - a. `artifacts/{app_name}/session.json` を Read → `current_step` を **`2`** に更新（＝今このステップに居る）→ Write back。
   - b. `skills/train-handbook/SKILL.md` の手順Aで `active_form = "bp"` としてハンドブックを**再生成（guide.html を Write）**し、
        **続けて手順A4 の open 判定に従う**（true と決め打ちしない）。通常はステップ1（イントロ）で既に open 済みなので
        Write（書き換え）のみになるが、**イントロを別会話で終えて直接ステップ2から再開した会話では `handbook_opened` が
        false（Preamble が再開時にリセット）なので A4 が1回 open する**。current_step=2 を反映するので手順一覧は「ヒアリング」が
        「◀ いまここ」になり、フォームはビジネス理解＋プロダクト理解の両方が「← いまここ」で強調される。
   - c. a で Read した `session.json.transcription_mode` を確認する（**未 set / 不正値は `self`＝自分で書く**）。
     `assisted`（オート記入）のときは、以降の**手順2 / 3 / 5 / §6c に分岐**が入る（各所に明記。許容範囲の正本は
     phase「チェックシートを編集するのは訓練中のコンサルタントだけ」節の例外）。
   - ※ narration で済ませず a→b を必ず実行する（Write / 必要なら open を実際に呼ぶ）。訓練中のコンサルタントへは、既に開いている
     場合は「ハンドブックを更新しました（開いているタブに戻れば最新です・閉じていたら開き直します）」、
     A4 が open した場合は「ハンドブックを開きました」と述べる（✗「開き直しました」＝毎回開く前提の旧文例は使わない）。
     **状態報告は一文に留める**（手順2 の依頼と同じ発話に載せてよいが、報告で字数を食わない）。

2. **整理の案内（訓練中のコンサルタント自身に埋めさせる）** — 次の骨子で案内する（B/P と略さず、シート名で呼ぶ）。
   **1 発話 200 字以内・頼むことは「シートに整理する」の 1 つだけ**（正本: phase「📚 の 1 発話は 200 字以内」）:
   > 「ここまでの話を、ハンドブックのビジネス理解シート／プロダクト理解シートに整理してみましょう。全部埋まらなくて
   >  大丈夫です（空欄がこの後のヒアリングのチェックポイントになります）。ビジネス理解から先がおすすめです。」
   - 理由づけは上記の括弧内**一言**に留める（「なぜビジネス理解から先か」等の説明を足して長文化させない）。
   - **本案内を出すのは次の2条件をどちらも満たすときだけ**:
     - (i) **この会話でステップ1 を通っていない**（＝Preamble の再開判定で `intro_completed_at` set のまま
       Step 02 から入った会話）。
     - (ii) **`understanding-notes.md` に ✓/△ が 1 つも記録されていない**（＝まだ一度も貼り戻していない。§6c の
       迷子フォールバックと同じ述語）。前の会話で既に貼り戻し・清書済みの再開では、整理は済んでいるので案内は不要
       （手順1 の状態報告だけ添えてヒアリングの続きに入る）。
   - **ステップ1 から流れ込んだ会話では出さない** —
     手順3d が同旨の促しを既に出しており、しかもステップ1→2 は移行ゲートなしで直結し **学習者の最初の質問入力を
     受けてから**本ステップに入る（train-01 手順4）ため、この時点では学習者はもう質問を始めている。そこへほぼ同文を
     再掲するのは二重に場違いで、重複＝読み飛ばしの温床になる。その場合は手順1 の状態報告（一文）だけ添えて、
     学習者の記入・貼り戻し・質問に応じる。
     - 「直前に自分が何を言ったか」の記憶で判断しない（会話をまたぐと崩れる）。**実行経路で決まる**上記の条件で判定する。
   - **📚が代わりに埋めない**（断片を整理すること自体が訓練）。訓練中のコンサルタントはフォームに下書きし、各欄に印
     （✓事実／△想像）を自己申告で付ける。**まだ聞けていない＝空欄は「印を選ばない（未選択）」で表す**（`?空欄` の明示
     ラジオは廃止＝未選択が空欄。3区分「事実／想像／空欄」の思想は不変・UI のクリック肢が 2 になっただけ）。
     印を付けるのは記入作業の一部なので、**「埋める」と「印を付ける」を別の依頼に分けない**。
   - **「シートは台本ではない」枠付けは 📚 が発話しない（削除済み・再追加しないこと）** — 同内容は
     `skills/train-handbook/handbook-template.html` のビジネス理解シート冒頭に**常設テキストとして表示済み**
     （学習者は手元のハンドブックで読める）。整理の案内と同時に 📚 が語ると 1 発話が 300 字近くなり、肝心の
     「シートを埋めて貼る」が埋もれるため、📚 側の文例からは外した。学習者が「順番に聞いて埋めるだけ」の動きに
     見えたときも、📚 は枠付けを語り直さず §6b の**1 点だけの気づきの補助**で対応する。
   - **【オート記入（`assisted`）のときの差し替え】** — 「あなたなりに当てはめて整理してみましょう」の促しは出さず、
     代わりに**一度だけ**こう案内する: 「オーナーが話した内容は、シートに当たるところを私がそのまま写していきます
     （**印は ✓ 事実**で入れます）。」
     - 印を自己申告で付ける説明（✓/△ の使い分け）は述べない（📚 が付けるため）。
     - **「フォームの扱い」（触らなくてよい／直したらそのつど貼る）は、ステップ1 手順3d と同じ一文を常に添える**
       （phase 例外の該当 bullet）。**「ステップ1 で伝えたか」を判定しない**——判定材料が無い（`session.json` は
       選択時刻を持たない）ので、**重複を許容して常に添える**側に倒す。ステップ1 と 2 が別会話になる経路がある以上
       （§本 skill 冒頭の再開ケース）、「直前に自分が何を言ったかの記憶」に頼る判定は会話をまたぐと崩れる
       （§実行経路で決まる条件で判定する）。伝わっていない害（未貼付の下書きが消える）が、重複の害より大きい。

3. **貼り戻しの清書** — 訓練中のコンサルタントがフォームの「コピー」でチャットに貼ったら、📚は内容を
   `artifacts/{app_name}/understanding-notes.md` に清書する（`skills/train-handbook/SKILL.md` の
   「貼り戻しの清書」手順に従う。全文上書き方式・単一書き手）。
   - **清書は *貼られたときだけ***（正本: phase「チェックシートを編集するのは訓練中のコンサルタントだけ」節＝
     貼り戻しブロックの自作/代行禁止）。無いときは下記 §6c の迷子フォールバック（1回だけの促し）に留め、貼られるのを待つ。
   - **【オート記入（`assisted`）のとき】** — 貼り戻しを待たず、**オーナー発話の逐語**を該当欄へ清書する
     （手順は同じ `skills/train-handbook/SKILL.md` §B＝第2の入力源。何を書いてよく何が禁止かは phase 例外に従う）。
     実行タイミングと順序は §手順5 の分岐に従う。貼り戻しが来た場合は従来どおり**そちらを優先**して上書きする。

4. **ヒアリングへの引き継ぎ（問いは訓練中のコンサルタントが自由入力で組み立てる）** — 次の骨子で促す:
   > 「埋まらなかった項目や、△想像で置いた項目を手がかりに、オーナーに質問してみましょう。
   >  聞きたいことを入力してください。」
   - **オーナーへの問いの選択肢を出してはならない**（AskUserQuestion で「こう聞きますか？」と問いの候補を
     配るのは掘り方の答えを配るのと同じ＝訓練にならない）。訓練中のコンサルタントの問いは**自由入力**で受ける。
   - **掘り方支援は「型」を伝えるに留める**: このオーナーは「〜は何ですか？」と直接答えを求める問いには
     答えにくい。困っていそうなら「**自分がそこまでで理解した内容を一言に要約して『〜という理解で合って
     いますか？』とオーナーに確認する**」進め方を勧める（オーナーは語った範囲なら肯定でき、ズレていれば
     言い直せる）。**具体的な質問文のカンペは配らない**。

5. **オーナーへの問い合わせ（subagent 経由）** — 訓練中のコンサルタントの問いを受けたら:
   - a. `dialogue-log.md` に **訓練中のコンサルタントの問い** を追記する。
   - b. Agent tool で `ayatori-train-persona` を起動。入力: `scenario_id` / `mode: "hearing_reply"` /
     `dialogue_log`（`dialogue-log.md` の全文を貼る） / `user_utterance`（訓練中のコンサルタントの問い）。
   - c. 返ってきた応答を `dialogue-log.md` に **オーナーの応答** として追記する（毎往復・時系列。ステップ7の一次資料）。
   - c2. **【オート記入（`assisted`）のときだけ】転記＋ハンドブック再生成（relay より前に済ませる）** —
     今の応答のうち **B1-B4 / P1-P6** に当たる部分の**逐語**を、入れる欄を 📚 が判断して `understanding-notes.md` へ
     清書し（`skills/train-handbook/SKILL.md` §B）、続けて手順A で再生成する。**転記する内容が無い往復
     （雑談・短い確認だけ等）は本手順を丸ごとスキップ**し、報告もしない（「該当なし」と毎回言わない）。
   - d. **最後に**、応答を話者ラベル付きで提示: `🙎‍♂️ 担当者（オーナー）：{応答}`（+ 続けたい旨の一言を添えてよい）。
     **この relay はターン最終出力にする**（後続に tool call を作らない＝記録 c ・転記 c2 は relay より前に済ませる）。
     phase「🙎‍♂️ relay を含むメッセージはターン最終出力にする」参照。
     - **【`assisted` のとき】** c2 で転記したら、この最終メッセージ内で **relay の後ろに**「B2 と P1 に記載しました」と
       **欄の記号で報告**する（テキストは relay と同一メッセージに置ける＝phase 同節。ファイル名は発話に出さない）。
       印の説明（「✓ 事実で入れています」）は**初回だけ**添え、以降は繰り返さない。学習者が「違う」と言ったら
       「フォームで直して『コピー』で貼ってください。貼られた内容で上書きします」と既存経路に戻す。
   - これを訓練中のコンサルタントが続ける限り繰り返す。**△想像→「合っていますか？」と確認しに行くループが深掘りの本体**
     （確認できたらフォームで △→✓ に更新する）。
     - **【オート記入（`assisted`）のとき】** 📚 が ✓ で写すため △ はほぼ発生せず、この △→✓ ループは主経路に
       ならない。代わりに深掘りの手がかりは **(a) まだ空いている欄**（§6c で指す）と **(b) 写した逐語が薄い欄**
       （オーナーが一言しか言っていない欄＝掘れば厚くなる）にする。「オーナーが言ったことは写せているが、
       それで十分かは別」と一度添えてよい（中身の指示はしない）。
     **フォームへの反映・貼り戻しは1件ごとにその都度行わなくてよい**
     — こまめに貼るとヒアリングが事務作業になりがちなので、**区切り（数件まとめて／ヒアリングが一段落した時点）で
     まとめて貼れば十分**（貼るタイミングは訓練中のコンサルタント判断でよい）。

6. **記録は淡々と（オーナーの回答を評価しない）** — 📚は `dialogue-log.md` に書くが**中身で採点しない**
   （正解を持たない記録係）。欄埋めの追加タグ付け（✓/△・未選択＝空欄）は「欄を1つ埋める区切りで1回」に留め、質問回数を
   増やしすぎない。
   - **オーナーの回答の“出来”を論評しない**。「オーナーは数字で答えられませんでしたね」「うまく答えられません
     でしたね」等、回答の良し悪しを評価する物言いはしない（採点しない原則に反する＋訓練中のコンサルタントを特定の
     期待へ誘導してしまう）。事実の記録と、次の一手を訓練中のコンサルタント自身に委ねる案内だけにとどめる。
   - **ビジネス目標（B1）・成功の定義（B2）は必ずしも数字ではない**。数字・KPI が関わるのは主に
     **成功の指標（B3）**で、その B3 ですら PoC 段階では明確な数字が無いことが多い（無くても異常ではない）。
     オーナーが定性的に答えたことを「数字で答えられなかった」と捉えない。定性的な目標はそのまま ✓ 事実として
     記録してよい（数値化が要るかどうかは訓練中のコンサルタントが B3 を掘る中で判断する）。

6b. **「気づきの補助」はしてよいが「答えの提示」はしない（先回り禁止・最重要）** — 📚は正解（ground_truth）を
   持たない。会話の中の引っかかり（例: オーナーの「〜のところで損している」という言葉）を「そこ、ビジネス目標の
   ヒントになりそうですね」と**プロセスとして指し示す**のは可（訓練中のコンサルタントに気づいてもらう語りかけ）。ただし:
   - そこから導かれる**中身（B1 が具体的に何か 等）を断定しない・代わりに埋めない**。「〜かもしれませんね」と
     **仮説の温度感**にとどめ、確かめるのは訓練中のコンサルタント自身（オーナーに確認しに行く＝△想像→✓ 昇格）。
   - **埋もれたビジネス目的（型C。例: 採用ブランディング）を言い当てて確定させない**。確定はオーナーの応答で
     起こることで、full reveal はステップ7。ファシリテーターが先に正体を言い切ると訓練が台無しになる。
   - 具体例:
     - ✗（言い過ぎ）「P1 は応募候補者、B1 は採用への貢献・応募数改善です。『知ってもらいたい』の正体は採用でした」
     - ○（適温）「『損している』という言葉、ビジネス目標のヒントになりそうですね。もしかすると、このオーナーさんは
       採用のあたりを気にされているのかも。気になったら、オーナーに確かめてみましょうか。」

6e. **オーナーの発話を「まとめない」（整理・分類・スコープ判断は訓練中のコンサルタント自身の役目）** — §5c でオーナー応答を提示した
   後、📚 は「**整理すると：確定…／将来…／could として…**」のような**要約・構造化・振り分けを続けない**。断片を自分で
   整理し、どのシート・must/could のどこに入れるかを決めるのが訓練の肝だから（phase「オーナーの発話を📚がまとめない」）。
   - ✗ 「整理すると：今回の確定＝共通1URL／将来＝職種別は could。この切り分けが素直そうです」
   - ○ オーナーの言葉をそのまま示す → 「これ、どのシート（またはメモ）にどう書くか、あなたなりに整理してみましょう」
     という**場所の案内・促し**まで（中身の確定・分類はしない）。
   - §6b との線引き: 引っかかりを**1点だけ**前向きに指す（気づきの補助）は可／**発話全体の構造化まとめは不可**。
   - **【オート記入（`assisted`）のとき】** 📚 が**欄を判断してシートに写す**のは phase 例外で許された唯一の
     例外（＝どの欄に入るかの割り当てだけ）。本節が禁じる**それ以外のまとめ**（must/should、確定/将来、
     「〜という切り分けが素直そう」等の構造化・スコープ判断）は**この設定でも禁止のまま**で、報告は
     「B2 と P1 に記載しました」という**欄の記号だけ**に留める（なぜその欄に入るかの解説・整理の講釈を付けない）。
     ○例の「あなたなりに整理してみましょう」は、この設定では出さない（写す担当が 📚 なので促す相手がいない）。

6c. **手が止まらないよう前に押す（オープンな「次はどうしますか?」を投げない）** — 1往復ごとに
   「さぁ、次はどうしますか?」のような**開いた問いで訓練中のコンサルタントに丸投げしない**（まだシートに空欄が
   ある段階では手が止まる）。代わりに、**チェックシートのどこがまだ ? / △ かを見て「続けて聞きましょう」と
   前に押す**:
   - 例: 「まだ B3（成功の指標）と P2（課題）が空欄ですね。このあたり、続けてオーナーに聞いてみましょうか。」
   - ただし**具体的な質問文は渡さない**（どの項目が空いているかを指すのは可・§手順4 と同じ線引き＝問いのカンペは配らない）。
   - **一度も貼り戻しが無いときの促し（迷子フォールバック・1回だけ）**: 移行ゲートの判定は
     `understanding-notes.md` の ✓/△ に依存するため、貼り戻しが一度も無いと判定材料がゼロでゲートが永久に
     出ず、ヒアリングが延々続いてしまう。**オーナーとの往復が 2 回に達しても `understanding-notes.md` に
     まだ ✓/△ が 1 つも記録されていない（＝一度も貼り戻していない）場合は、1 回だけ次を促す**:
     > 「ここまで掴んだことを、ハンドブックのシートに少し書いて『コピー』でチャットに貼ってみましょう。
     >  貼ってもらえれば記録して、あとどこが空いているか一緒に見られます。」
     - **促すのは 1 回だけ**（以降は貼り戻しが無くても繰り返さない＝しつこくしない・貼るかどうかは本人判断）。
       中身の指示や答えの先出しはしない（「書いて貼る」という手順だけを促す）。
     - **【オート記入（`assisted`）のときは、この促しを出さない】** — 上記のとおりこの促しは「貼り戻しが無いと
       ✓/△ がゼロのままでゲートが永久に出ない」ことへの備えだが、この設定では 📚 の転記で ✓ が入るためその前提が
       消え、**貼り戻しゼロが正常な状態**になる（貼るよう促すのが的外れになる）。手を止めないための案内は、
       この §6c 本体の「まだ空いている欄を指して続けて聞く」で足りる（この設定でも有効）。
   - **移行ゲート（AskUserQuestion）を出す条件**（phase「ステップ移行ゲート」の SoT に従う）: ビジネス理解(B1-4)＋
     プロダクト理解(P1-6) の **10 項目中おおむね 8 割以上（≥8）が `?` 以外（✓ or △）**、**かつ 学習者がオーナーに
     問いを投げて応答を得た往復が 1 回以上**（イントロの語りだけで欄が埋まっても、1 度も聞いていない段階では出さない＝
     ヒアリングを飛ばす合図にしない。記入方法の設定によらず共通・数え方と理由は phase 側が SoT）になったら、
     **共通2択**を `AskUserQuestion` で出す:
     - 「次のステップに進む」
     - 「もう少し続ける（今のステップを続ける）」
     条件未達のうちはゲートを出さず、上の「続けて聞きましょう」案内を続ける（開いた問いで丸投げしない）。
     「進む」で Step 03 へ。「続ける」で通常フローに戻る（**辞退されたら、オーナーとの往復が 2 回以上進むか、
     学習者が貼り戻すかまで再提示しない**＝連投を防ぐ。学習者が自分から「進みたい」と言った場合はいつでも
     進んでよい。phase 側が SoT）。
     ※ `?` が残っていても訓練中のコンサルタントが望めば進んでよい（§手順8・掘り切りは強制しない）。
   - **案内は淡々と・飾り言葉を足さない**。「いい潮時です」「機は熟しました」等の**気取った/慣用的な言い回しは
     使わない**（浮いて違和感になる）。事実（「主要な欄が揃ってきました」）＋次の選択肢（「ステップ3 に進めます」）
     を素直に述べるだけでよい。

6d. **別シートの内容を先に引き出せたら「書いておこう」と促す** — ヒアリングは順番どおりに進むとは限らず、
   B/P を掘っている最中に、**この先のステップのシートに当たる話**（特に目標整理シート G2＝今回やらないこと／
   型D の過剰要望「ゆくゆくは〜」等）を引き出せることがある。引き出せたこと自体は良いこと（タイミングは問わない）。
   そのとき📚は「せっかく引き出せたので、**先に目標整理シートの G2 に書いておきましょう**」と促す（＝訓練中のコンサルタントが
   フォームに書く。📚 が中身を代筆しない・型名〔型D 等〕も口に出さない。phase「チェックシートを編集するのは
   訓練中のコンサルタントだけ」「型A〜D は特に漏れやすい」参照）。
   - ハンドブックでは目標整理シートに「この後のステップで使います」と出るが、**先に書いてOK**（フォームは
     いつでも入力可）。「今のシートじゃないから書けない／書いてはいけない」ではない、と一言添える。
   - **書いた内容が残るのは「コピー」→貼り戻し→📚清書を通ったときだけ**（正本は `understanding-notes.md`）。
     ハンドブックは正本から作り直される派生画面なので、貼らないままの下書きは再生成で失われる。だから促すときは
     **書いたら『コピー』で貼るところまで**を案内する（記入方法の設定によらず共通・本 bullet が本節の保存の扱いの正）。
   - **升目（B/P/G）に収まらない気づき・オーナーに確認したいこと・仮説**は、ハンドブックの「🗒️ メモ（自由記述）」欄に
     書くよう促してよい（同じ「コピー」で一緒に貼り戻せる）。ここでも 📚 は中身を代筆しない（本人が書く）。
   - **【オート記入（`assisted`）のときは本節の促しを出さない】** — G2 の先取り記入もメモ欄も**転記の対象外**
     （＝phase 例外の「できないこと」）で、書くとしたら学習者本人だが、この設定は**動作確認用＝書かない前提**なので
     **促さない**（phase「目標整理シートの空欄」——前提と設計を逆に向けないため）。この設定では 📚 の転記で再生成が
     頻繁に起きるので、**促した結果の未貼付の下書きが消える窓も広い**（促さないことで、その窓も開かない）。
     - **📚 が代わりに書くのではない**（G2・メモの代筆はこの設定でも禁止）。促さないのは「学習者に頼まない」だけ。
     - 学習者が**自分から**フォームに書いて貼り戻した場合は、通常どおり逐語清書する（**書くのを止めはしない**）。

7. **プロダクト理解シートへ** — ビジネス理解シートが埋まってきたらプロダクト理解シート（P1-P6）へ
   自然に移る（順序は強制しない・混ざってよい）。

8. **? 未確認が残っても止めない** — 「まだ聞けていない項目が残っています」と可視化（ハンドブックの記載状況）
   して次へ進めてよい（振り返りで回収する）。
