# Step 00: シナリオ選択

**磨く力**: （導入の前段。ステップ0-1全体でビジネス理解の入口を作る）

**役割**: 📚AIファシリテーターが正解ファイルを一切開かずに実行する（教材の中身＝ground_truth は
`ayatori-train-persona` subagent だけが `scenario_id` で開く）。本ステップで読むのは
`skills/train-00-scenario-select/scenarios/index.json`（oneliner + difficulty のみ・正解を含まない）と
`artifacts/_train-profile/*.json` のみ。

## 手順

1. **`_train-profile/` の確認・初期化**
   - `artifacts/_train-profile/radar.json` を Read or `{ "axes": {} }` から初期化。
   - `artifacts/_train-profile/play-log.json` を Read or `{ "plays": [] }` から初期化。
   - どちらも未存在なら Write で新規作成（既存ファイルの上書きにはならない・新規作成のみ）。

1b. **初回のみ：トレーニング説明ページを開く（履歴が無いときだけ）**
   - **初回判定**: `play-log.json.plays[]` が**空**（＝これまで一度もシナリオを選んでいない）なら初回とみなす。
     `plays[]` に1件でもあれば経験者なので**本手順はスキップ**し、そのまま手順2（レーダー表示）→ 手順3以降の
     シナリオ選択へ進む。
   - **初回のときだけ**、次を行う:
     1. 説明ページ `skills/train-handbook/ayatori-train-explainer.html` を OS 既定の方法で開く
        （macOS=`open` / Linux=`xdg-open` / Windows=`cmd.exe /c start "" "<file>"`）。開けない環境ではファイルパスを
        提示する **link-only fallback** に degrade する（CLI 不在でエラー停止しない）。
     2. チャットで**3行程度**だけ軽く説明する（長文にしない）。骨子:「これは AI と事業側の"通訳"を鍛える練習です」
        「オーナー役と話して要件を掴み、AI が作ったものを人の目でレビューします」「詳しくは今開いたページを見てください」。
     3. `AskUserQuestion` で「シナリオ選択を開始しますか？」と確認する（開始／もう少し説明を読む 等の2択）。
        開始が選ばれたら手順2へ進む。
   - この分岐は初回体験の導入だけが目的で、経験者の毎回の起動を重くしない（経験者はシナリオ選択直行）。

2. **自己評価レーダーの表示**
   - `radar.json.axes` が空、または全軸が未入力の場合: 「初回のため自己評価レーダーは未入力です。ひとまずシナリオ選択に進みます」と案内する（レーダーはステップ7 で今回の気づきをもとにチャットで確定する＝たたき台方式。ステップ0 は過去の値の表示のみで入力フォームは開かない）。
   - 値がある場合: 6軸（ビジネス理解／ヒアリング／目標設定／目利き／補完／AI伝達）の現在地（L0-L3）を簡潔に一覧表示する。

3. **index.json の Read（唯一の許可ソース）** — `skills/train-00-scenario-select/scenarios/index.json` を Read
   （**これ以外の scenario ファイルは絶対に開かない**）。`scenarios[]` は難易度昇順→通し番号昇順で並んでいる。
   - **通し番号（ファイル名先頭の数字）＝難易度昇順で採番**（1-2=難易度0 / 3-4=難易度1 / 5-6=難易度2）。選択の一意化用。
   - `play-log.json.plays[]` に記録済みの `scenario_id` があれば「以前プレイ済み（ネタバレのため別がおすすめ）」と注記する。

4. **選択の確定＝二段構成（AskUserQuestion を2回）** — 選択肢は AYATORI パイプラインの制約で**最大4つ**。シナリオは
   4本を超えうるため、**まず難易度、次にその難易度内のシナリオ**の2段で選ばせる（4択制約を守りつつ全シナリオを提示できる）。

   **第1段：難易度を選ぶ** — `AskUserQuestion` で、index.json に実在する `difficulty` 値の集合を**昇順**で提示する
   （ハードコードしない＝将来値が増減しても index.json 由来で自動追従）。各選択肢は事実のみ:
   - ラベル例: 「難易度0（やさしい）」「難易度1（ふつう）」「難易度2（むずかしい）」。**やさしい/ふつう/むずかしい等の
     かっこ書きは difficulty 値の昇順位置から機械的に付ける**（0=やさしい・最大値=むずかしい・中間=ふつう。3段以外に
     増えたら中間は「ふつう」で丸めてよい）。説明文には各難易度に属するシナリオ本数を「N本」とだけ添える。
   - **★おすすめ（難易度側に付ける）**: `radar.json.axes.business_understanding` が低め（L0-L1 相当）なら**小さい
     difficulty**、高め（L2-L3 相当）なら**大きい difficulty**に「★おすすめ」を添える。レーダー未入力ならおすすめ無し。
   - その難易度に**1本しか無い場合でも第1段は出す**（体験の一貫性のため）。**難易度が1種類しか無い場合のみ**第1段を省略し
     第2段へ直行してよい。

   **第2段：その難易度内のシナリオを選ぶ** — 第1段で選ばれた難易度に属する項目だけを `AskUserQuestion` で提示する
   （同一難易度内は通常2本＝4択制約に収まる。将来1難易度が4本を超えたら別途分割を検討）。
   - 各選択肢＝「{通し番号}. {一言名}」+ 該当時のみ「以前プレイ済み」注記。並びは通し番号昇順。
   - 「戻る（難易度を選び直す）」に相当する明示選択肢は置かない（AskUserQuestion の ESC/Other で対応可能）。

   - **内部ルール（ユーザー向け文言に出さない）**: おすすめ表示は判断材料であって指示ではなく、AskUserQuestion 自体が
     選択を委ねている。よって「最終選択はあなた次第」「お好きに」等の**選択の主体を念押しする一言を、質問文・選択肢・
     前後の案内に一切添えない**（同義・言い換え含め発想として出さない）。委ねる姿勢は「余計な誘導文を足さないこと」で表す。

5. **セッション初期化**
   - `app_name` を決める: `_train-{scenario_id のうち番号を除いた slug}-{NN}`（例: `_train-owned-media-01`）。
     `NN` は `artifacts/` 配下の既存同一 slug ディレクトリの**最大連番 + 1**を振る（例: `-01` が既にあれば `-02`）。
     ディレクトリ数ではなく最大番号 +1 で採番するので、途中のディレクトリを手で消しても衝突しない。
   - `artifacts/{app_name}/session.json` を新規 Write:
     ```json
     {
       "app_name": "{app_name}",
       "scenario_id": "{選択された scenario_id}",
       "current_step": 1,
       "started_at": "{現在時刻 ISO8601}"
     }
     ```
   - `artifacts/_train-profile/play-log.json` の `plays[]` に追記（Read → merge → Write back）:
     ```json
     { "scenario_id": "{scenario_id}", "app_name": "{app_name}", "started_at": "{現在時刻}", "completed": false }
     ```

6. Step 01（イントロダクション）へ進む。
