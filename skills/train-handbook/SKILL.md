# train-handbook: ハンドブック生成・貼り戻し清書（共通ヘルパー）

**役割**: 訓練中のコンサルタントの相棒となる自己完結HTML「ハンドブック」を、現在の進行状態でその都度生成し、OS 同梱コマンドで
開く。ブラウザはローカルファイルを書けないため、フォーム入力は「コピー→チャット貼り戻し→📚が正本清書」方式
（貼り戻し方式）。📚AIファシリテーターが単一書き手として `understanding-notes.md` / `radar.json` を書く。

呼ばれる場面（`active_form` の値）:
- ステップ1 → `null`（**ハンドブック初出・ここで初めて生成＋自動オープン**。今ここ＝イントロ・フォームはまだ非強調） /
  ステップ2 → `"bp"`（ビジネス・プロダクト理解／再生成のみ・open 済み） /
  ステップ3 → `"goal"`（目標整理） / ステップ4 → `null` / ステップ7 → `"radar_update"`
- ステップ0 では開かない（ステップ0 はレーダー表示とシナリオ選択のみ）。

## A. ハンドブックの生成・再生成

1. **テンプレートを Read** — `skills/train-handbook/handbook-template.html`。この中に差込点
   `<script id="ayatori-train-state" type="application/json">{{STATE_JSON}}</script>` が1つある。
2. **状態 JSON を組み立てる** — 現在の artifact から下記を集める（無い項目は空/`null`）:
   - `app_name` / `scenario_oneliner`（`session.json.scenario_id` を index.json の oneliner に解決。**正解
     ファイル本体は開かない**・index.json のみ） / `current_step`（`session.json`。**呼び出し元の各ステップが
     入口でこの値を「今のステップ番号」に更新してから本手順を呼ぶ**ので、その値をそのまま反映する。これで
     手順一覧の「◀ いまここ」が今のステップに一致する）
   - `active_form`（呼び出し元が指定）
   - `business` B1-B4 / `product` P1-P6 / `goal` G1-G2 ＝ `understanding-notes.md` の現在値（各欄 `value` と
     `mark`。未記入は `value:""`, `mark:"?"`）
   - `radar` 6軸 ＝ `artifacts/_train-profile/radar.json` の現在値（未評価は `null`）
   - `notes` ＝ `understanding-notes.md` の `## メモ` 節の現在値（自由記述文字列。無ければ `""`）
   JSON 形は `handbook-template.html` 冒頭コメントおよび本 skill 末尾「状態JSONの形」を参照。
3. **差込 → Write** — テンプレート中の `{{STATE_JSON}}` を、組み立てた JSON 文字列（`<` を `\u003c` に置換して HTML-safe にしたもの）に**1:1 置換**して
   `artifacts/{app_name}/guide.html` に Write（テンプレートの他の部分は逐語コピー・改変しない）。
   - **安全な差込**: 値は自由記述なので `</script>` が混ざりうる。script タグが途中で閉じないよう、差し込む JSON 文字列中の `<` は必ず `\u003c` に置換する。
   - **導線リンクは複製しない（相対パスで repo 内マスターを直接開く）** — ヒーローの「▶ トレーニングモードって何？」
     リンクは `../../skills/train-handbook/ayatori-train-explainer.html`（＝ repo 内のマスター）を指す。`guide.html` は
     常に `artifacts/{app_name}/`（repo ルートから2階層下）に生成されるため、この相対パスで確実に解決する。
     スライドを `artifacts/` へコピーしない（単一マスター・二重管理を避ける。マスターはコミット済みなので他環境でも存在する）。
   - **確定済みの値を必ずプレフィルする**（再生成のたびに最新が土台になる＝全文上書き方式と整合）。
   - `active_form` は当該フォームを「← いまここ」で先頭強調するだけでなく、**この段階でまだ不要なフォームに
     「この段階ではまだ（今は不要）」バッジ＋薄暗表示を自動付与**する（例: ステップ2＝`bp` のとき目標整理・
     レーダーは「まだ」表示）。よって📚が口頭で「目標整理シートは今は書かなくていい」等と説明する必要はない
     （ハンドブックの表示に委ねる）。
4. **自動オープン（初回のみ）** — ハンドブックは同じタブが開きっぱなしでも、タブに戻るたびに自動リロードして
   最新化する仕組み（`handbook-template.html` の visibility/focus リスナー）を内蔵する。よって **open するのは
   このセッションで最初の1回だけ**にし、2回目以降の再生成では Write（書き換え）だけ行い open しない（古いタブが
   ブラウザに溜まるのを防ぐ）。判定は `session.json` の `handbook_opened` フラグで行う:
   - `session.json` を Read（無ければ init stub）。`handbook_opened` が `true` **でない** 場合のみ、下記 OS 同梱
     コマンドで開き、`handbook_opened: true` を merge して Write back する（Read → merge → Write back）。
   - すでに `true` の場合は open せず、Write（差込済み `guide.html` の上書き）だけで完了。訓練中のコンサルタントには
     「ハンドブックを更新しました。開いているタブに戻ると最新になっています（もし閉じていたら教えてください、開き直します）」
     と一言添える（✗「開き直しました」＝毎回 open する前提の旧文例は使わない）。
   - **例外: タブを閉じた／見当たらないとき（自動リロードが効かない）** — 自動リロードは「開いたままのタブ」でしか
     働かない。訓練中のコンサルタントが「閉じてしまった」「見当たらない」と言ったとき、または明示的に「開き直したい」と
     求めたときは、`handbook_opened` が `true` でも **もう一度 open してよい**（オンデマンド再オープン。`handbook_opened`
     は `true` のまま）。求められていないのに毎回 open しない原則は保つ。
   - OS 同梱コマンド（外部 CLI に依存しない・CLAUDE.md Operating Principle 1 の OS 同梱例外）:
     - macOS: `open "artifacts/{app_name}/guide.html"`
     - Linux: `xdg-open "artifacts/{app_name}/guide.html"`
     - Windows: `cmd.exe /c start "" "artifacts/{app_name}/guide.html"`
   - コマンド不在／失敗時は**エラー停止せず**、ファイルの絶対パスを提示して「ブラウザで開いてください」に degrade
     （この場合も `handbook_opened: true` は立てる＝二重案内を避ける）。

## B. 貼り戻しの清書（フォーム → 正本）

訓練中のコンサルタントがハンドブックの「コピー」ボタンで出したテキストブロックをチャットに貼ったら、📚が正本に清書する。
貼り戻しテキストは `【AYATORI-TRAIN ハンドブック貼り戻し】` で始まり、`--- {シート名} ---` 区切りで
各欄が `{項目} [{マーク}]: {値}` 形式（目標整理はマーク無し、レーダーは `{軸}: L{n}` or `-`）。
**末尾の `--- メモ ---` 以降は自由記述の本文**（複数行になりうる・EOF まで全部がメモ本文）。

> **禁止則の正本はここでは持たない（SoT＝phase）**: 「📚 は代筆しない・貼り戻しブロックを自作/代行しない・
> 清書は貼られたときだけ」の禁止則の**正本は `phases/train/SKILL.md`「チェックシートを編集するのは
> 訓練中のコンサルタントだけ」節**（失敗例含む）。本 skill での要旨は1行のみ: **📚 は貼り戻しテキストの値を
> そのまま写す（足さない・言い換えない・来るまで待つ）**。**清書したら必ず A の手順でハンドブックを再生成**し、
> 書いた内容が訓練中のコンサルタントの画面に反映された状態にする（正本だけ更新して裏で持ったままにしない）。

> **第2の入力源（`session.json.transcription_mode == "assisted"` のときだけ）**: 学習者が「オート記入」を
> 選んだ場合、貼り戻しブロックが無くても **オーナー発話の逐語**を入力源として本節の清書手順で書いてよい（欄の判断と
> ✓ 付与は 📚 が行う。`--- {シート名} ---` 形式のパースは不要＝発話から直接。書き方は下記 1〜2 と「understanding-notes.md
> の形」に従い、全文上書き・メモ / 振り返り節の保全も同じ）。「来るまで待つ」は `self`（既定・未 set 含む）のときの
> ルール。**貼り戻しが来たらそちらを優先**して上書きする。何を書いてよく何が禁止か（許容範囲）の正本は上記 phase 節の
> 例外だが、**書式は本節が持つ**: 既存値に足すときは `{既存の値} ／ 追記：{新しい逐語}` の形で**同じ行に**続ける
> （上記のとおり1欄=1行でパースするため、**欄の中で改行しない**——改行すると学習者が貼り直したときに壊れる）。
> **貼り戻しブロックを 📚 が自作する禁止は解除されない**（転記は本節の清書で直接行い、人間の入力操作をシミュレートしない）。

1. **理解シート・目標整理シート → `understanding-notes.md`** を**全文上書き**で清書する（差分追記しない＝
   二重記載・欠落回避・単一書き手）。フォーマットは本 skill 末尾「understanding-notes.md の形」に従う。**清書後は
   A の手順で再生成**（プレフィル更新）して反映を見せる。
   - **上書きの直前に、いま保存されている正本を必ず Read する**（読まずに書かない）。そのうえで、**今回書く欄は
     既存の値に追記**し（置き換えない・印も変えない＝上記「第2の入力源」の追記書式および phase「既に値がある欄は
     消さずに書き足す」）、**それ以外の欄とメモは現在値を逐語でそのまま持ち越す**。**どの欄も、いま入っている内容が
     消えない**ことを確認してから Write する。
     - 全文上書き方式なので、**書かない欄も毎回書き直す対象**になる。**学習者しか書けないもの**
       （`## メモ`、G1・G2、学習者がフォームで直した B/P の値と印）は落とすと**復元できない**——特にオート記入では
       上書きがオーナーの発話ごとに増え、学習者は貼り戻していないので**チャットに控えが無い**。
2. **メモ → `understanding-notes.md` の `## メモ` 節**（`## 振り返り` の上）へ、`--- メモ ---` 以降の本文を
   **そのまま逐語**で清書する（1 の全文上書きに含めて書く＝メモが消えない）。📚 はメモの中身を書かない・足さない・
   要約しない（中身を書くのは訓練中のコンサルタント本人のみ。空なら空節のまま）。
3. **レーダー → `artifacts/_train-profile/radar.json`** を更新（Read → merge → Write back）。`axes.{軸キー}` に
   0-3 を入れる（`-` は未評価＝該当キーを更新しない or `null` 維持）。軸キー:
   `business_understanding` / `hearing` / `goal_setting` / `discernment` / `complement` / `ai_communication`。
   - **レーダーだけは「たたき台方式」**（ステップ7・`train-07-retro` Phase 5）: 📚 が今回の気づきから L 値の**下書きを提案**し、
     訓練中のコンサルタントがチャットで確認・修正して合意した値を清書する（B/P/G/メモの「AI は中身を書かない」とは扱いが異なる）。
     主経路はチャット確認だが、フォームで直して貼り戻された場合はその値を優先して清書する。**採点ではなく本人が納得した自己評価**である点は保つ。
4. 清書後、必要なら A の手順でハンドブックを再生成（プレフィル更新）→ 記載状況を最新化して開き直しを案内。

## 状態JSONの形（handbook-template.html が期待する構造）

```json
{
  "app_name": "_train-owned-media-01",
  "scenario_oneliner": "企業オウンドメディア",
  "current_step": 2,
  "active_form": "bp",
  "business": { "B1": {"value":"","mark":"?"}, "B2": {"value":"","mark":"?"}, "B3": {"value":"","mark":"?"}, "B4": {"value":"","mark":"?"} },
  "product":  { "P1": {"value":"","mark":"?"}, "P2": {"value":"","mark":"?"}, "P3": {"value":"","mark":"?"}, "P4": {"value":"","mark":"?"}, "P5": {"value":"","mark":"?"}, "P6": {"value":"","mark":"?"} },
  "goal": { "G1": {"value":""}, "G2": {"value":""} },
  "radar": { "business_understanding": null, "hearing": null, "goal_setting": null, "discernment": null, "complement": null, "ai_communication": null },
  "notes": ""
}
```
- `mark` ∈ { "✓"（事実）, "△"（想像）, "?"（空欄） }。`radar` 各軸 ∈ { null, 0, 1, 2, 3 }。`notes` は自由記述文字列（複数行可・無ければ `""`）。

## understanding-notes.md の形（📚が単一書き手・全文上書き）

```markdown
# 理解ノート — {app_name}

## ビジネス理解シート
- B1 ビジネス目標 [✓]: {値}
- B2 成功の定義 [?]: {値}
- B3 成功の指標 [△]: {値}
- B4 背景（なぜ投資するか） [?]: {値}

## プロダクト理解シート
- P1 対象ユーザー [?]: {値}
- （…P6まで）

## 目標整理シート
- G1 一言ゴール: {値}
- G2 今回はやらないこと: {値}

## メモ
{訓練中のコンサルタントの自由記述をそのまま・複数行可。無ければ空}

## 振り返り
（ステップ7で追記）
```
> **節の順序が重要**: `## メモ` は必ず `## 振り返り` の**上**に置く。ステップ7 は「振り返り」節のみ全置換するため、
> この順序ならメモはステップ7 でも消えない。また B/P/G の貼り戻しは understanding-notes を**全文上書き**するので、
> 上書き時は毎回この `## メモ` 節（現在値）も含めて書く（含め忘れるとメモが消える）。**ステップ7 で `## 振り返り`
> 節が書かれた後に貼り戻しで全文上書きする場合は、`## 振り返り` 節の現在値も同様に含めて書く**（含め忘れると振り返りが消える）。
