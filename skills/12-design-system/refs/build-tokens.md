# Build tokens.json (Style Dictionary v5)

## Overview

Build tokens.json generated by `generate-tokens.md` into multi-platform outputs using Style Dictionary v5.
Generates config with custom transforms to ensure correct compilation on all target platforms.

## Input

| File | Required | Content |
|---|---|---|
| `artifacts/{app_name}/tokens.json` | ✅ | W3C DTCG-compliant tokens from `generate-tokens.md` |
| `artifacts/{app_name}/requirements.json` | ✅ | `design_output_scope.platform_combo`, (when mobile included) `design_output_scope.mobile_framework`, and `design_output_scope.legacy_android_xml` (missing = `false`) for platform filtering |

## Output

Output files depend on `platform_combo`, `mobile_framework`, and `legacy_android_xml` in requirements.json.

**Native co-emission policy:** When `platform_combo` includes mobile, native tokens (Swift + Compose) are **always emitted** as a safety net for platform-specific code paths (Platform Channels in Flutter, native Swift UI in KMP, etc.), regardless of `mobile_framework` value. Flutter / KMP outputs are added on top of the native baseline.

**Android XML is legacy opt-in:** Android View-system XML (`colors.xml` / `dimens.xml`) is **NOT part of the native baseline**. It is emitted only when `design_output_scope.legacy_android_xml == true` (View システムを使うレガシー案件: 既存アプリが XML ベース / レガシー画面の解析・改修 / View ベースのカスタムビュー / Compose への移行プロジェクト)。フィールド欠落 or `false` = 出力しない (新規 Compose 案件のビルド成果物に未使用 XML を残さない)。

| `platform_combo` | `mobile_framework` | Files generated | Count |
|---|---|---|---|
| `web_only` | (n/a) | css, scss, ts (4 web files) | 4 |
| `mobile_only` | `native` | ios-swift, compose | 2 |
| `mobile_only` | `flutter` | native baseline (2) + `build/flutter/tokens.dart` | 3 |
| `mobile_only` | `kmp` | native baseline (2) + `build/kmp/StyleTokens.kt` | 3 |
| `mobile_and_web` | `native` | web (4) + native baseline (2) | 6 |
| `mobile_and_web` | `flutter` | web (4) + native baseline (2) + flutter (1) | 7 |
| `mobile_and_web` | `kmp` | web (4) + native baseline (2) + kmp (1) | 7 |

Native baseline = `build/ios-swift/StyleTokens.swift`, `build/compose/StyleTokens.kt`.

When `legacy_android_xml == true` (and `platform_combo` includes mobile), `build/android/colors.xml` + `build/android/dimens.xml` are added on top of the counts above (**+2**).

## Prerequisites

- Node.js v22+
- **repo root で `npm ci` 実行済み** (`package.json` で `style-dictionary@5.4.0` を厳密固定。`node_modules/.bin/style-dictionary` が存在することが前提)

> **環境依存の install を避ける設計**: かつてはプロジェクトごとに `/tmp/sd-{app_name}/` で `npm init` + `npm install style-dictionary@5` を ad-hoc 実行していたが、(a) 実行時間がかかる、(b) ネットワーク不通時にブロック、(c) version drift のリスク、(d) subagent の sandbox 拒否で失敗、の 4 点を理由に廃止。現在は repo root の `package.json` / `package-lock.json` で version を lock し、`npm ci` を **1 回** 実行すれば全プロジェクトで再利用できる。
>
> `npx style-dictionary build --config config.mjs` は Node の module resolution により、config.mjs を `artifacts/{app_name}/build/` に置いた状態でも repo root の `node_modules/.bin/` を上位ディレクトリ解決で自動的に見つける。temp dir / npm init は不要。

## Agent Prompt

When executing this skill, follow Steps 1–4 in order.

---

### Step 0: Determine Target Platforms

Read `artifacts/{app_name}/requirements.json` and extract:
- `design_output_scope.platform_combo` (`web_only` / `mobile_only` / `mobile_and_web`)
- `design_output_scope.mobile_framework` (`native` / `flutter` / `kmp`) — present iff `platform_combo` includes mobile
- `design_output_scope.legacy_android_xml` (boolean) — missing = `false`

Map the values to the set of platforms to include in config.mjs:

| `platform_combo` | `mobile_framework` | Platforms |
|---|---|---|
| `web_only` | (n/a) | css, scss, js |
| `mobile_only` | `native` | ios-swift, compose |
| `mobile_only` | `flutter` | ios-swift, compose, flutter |
| `mobile_only` | `kmp` | ios-swift, compose, kmp |
| `mobile_and_web` | `native` | css, scss, js, ios-swift, compose |
| `mobile_and_web` | `flutter` | css, scss, js, ios-swift, compose, flutter |
| `mobile_and_web` | `kmp` | css, scss, js, ios-swift, compose, kmp |

**Native co-emission rule:** Whenever `platform_combo` includes mobile, the native baseline (`ios-swift`, `compose`) is always included regardless of `mobile_framework`. Flutter / KMP platforms are *added on top of* the native baseline.

**Legacy Android XML rule:** Add the `android` platform to the set **only when** `platform_combo` includes mobile **and** `legacy_android_xml == true`. `android` is never included for `web_only`, and never included when `legacy_android_xml` is missing or `false`.

Keep this platform set in context — it is used in Step 2 to filter which platform blocks to include.

---

### Step 1: Validate Input

Before generating the config, verify that tokens.json is well-formed:

**1a.** Read `artifacts/{app_name}/tokens.json`

**1b.** Check required structure exists:
- `global.color` — at least `primary`, `background`, `on-surface` must exist
- `global.spacing` — at least `md`, `touch-target` must exist
- `global.border-radius` — at least `md` must exist
- `global.shadow` — at least `sm` must exist
- `component` — at least `button` must exist

**1b-dual.** **Dual-mode detection — symmetric D1-a**: Walk tokens.json and check whether **any** color token has a `modes` sub-object containing both `dark` and `light` children with `$value` (例: `global.color.bg.modes.dark.$value` + `…modes.light.$value`). If present:
- Set `dualMode = true` for downstream use (config.mjs custom format selection).
- Validate **対称性**: every `modes.dark` leaf has a matching `modes.light` leaf in the same parent, and vice versa. Asymmetric modes (dark-only or light-only) are a validation error — stop and report.
- Validate **alias 整合**: semantic / component color aliases reference mode-specific paths (`{global.color.primary.modes.dark}` 等)。`{global.color.primary}` のような mode 抜きアラインは dual-mode 下では `Cannot resolve reference` を引き起こすため、検出時は generate-tokens.md にフィードバックして再生成を促す。
- **theme-agnostic な値** (spacing / typography / shadow 等) は `modes` を持たず flat のまま。これは想定挙動。
- If no `modes` sub-objects are found (single-mode / legacy): `dualMode = false`, behave identically to legacy builds (flat `global.color.{name}.$value` 構造)。

**1c.** Check format rules:
- All `$type: "dimension"` tokens have `{value, unit}` object format (e.g., `{"value": 12, "unit": "px"}` not `"12px"` or `"12"`)
- All `$type: "shadow"` tokens have DTCG composite object values (not CSS strings). offsetX/Y/blur/spread are `{value, unit}` objects; color is `{colorSpace, components, alpha}` object
- All `$type: "color"` tokens have hex string values (e.g., `"#38BDF8"`)

**If validation fails**: Stop and report the issue. Do not proceed to build. The issue should be fixed in `generate-tokens.md` and tokens.json regenerated.

---

### Step 2: Generate config.mjs

`artifacts/{app_name}/build/` ディレクトリを `mkdir -p` で確保し、config.mjs を **その直下** に Write する。temp dir (`/tmp/sd-*`) や `npm init` は使わない (Prerequisites 参照)。

Replace `{source_path}` and `{build_path}` with actual directory paths:
- `{source_path}` → `../tokens.json` (config.mjs から見た相対パス。tokens.json は `artifacts/{app_name}/` 直下にあるため)
- `{build_path}` → `.` (config.mjs と同じディレクトリ。Style Dictionary は relative にこのパスから書き出す)

**Platform filtering:** Include only the platform blocks determined in Step 0. Omit all other platform blocks from the `platforms:` section entirely.

**Critical design decision:**
- **Web (CSS/SCSS/JS)**: Use built-in `transformGroup` (no issues with DTCG format)
- **Mobile (Swift/Kotlin/Dart/Android)**: Do NOT use `transformGroup`. List all transforms explicitly in `transforms`

Reason: Combining `transformGroup` with `transforms` causes custom transforms to interfere with built-in transforms, breaking name resolution and value conversion (confirmed in verification #2).

#### Config Template

```javascript
// M1: mobile platforms materialize only the dark mode of
// theme-aware tokens (path contains "modes"). Tokens without "modes" in path
// (theme-agnostic: spacing / typography / shadow / etc.) pass through.
// A future M2 ticket will introduce per-mode mobile output.
const mobileDualFilter = (token) => {
  const idx = Array.isArray(token.path) ? token.path.indexOf("modes") : -1;
  if (idx === -1) return true;                      // mode-agnostic → include
  return token.path[idx + 1] === "dark";            // dual-mode token → keep dark only
};

export default {
  source: ["{source_path}"],
  log: {
    verbosity: "verbose",
  },
  hooks: {
    transforms: {
      // dimension type: DTCG {value, unit} object → number
      // Built-in size/rem → remToCGFloat chain cannot correctly process
      // DTCG object format. Extract numeric value directly from the object.
      // Handles both DTCG object format {"value": 16, "unit": "px"} and legacy "16px" string.
      "dimension/pxToNumber": {
        type: "value",
        filter: (token) => token.$type === "dimension",
        transform: (token) => {
          const raw = token.original?.$value ?? token.$value ?? token.value;
          if (typeof raw === "object" && raw !== null && "value" in raw) {
            return raw.value;
          }
          return parseFloat(String(raw));
        },
      },

      // fontFamily type: wrap as string literal with quotes
      // Not needed for CSS, but Swift/Kotlin/Dart output without quotes causes compile errors
      "fontFamily/quotedMobile": {
        type: "value",
        filter: (token) => token.$type === "fontFamily",
        transform: (token) => {
          const raw = token.original?.$value ?? token.$value ?? token.value;
          return `"${String(raw)}"`;
        },
      },

      // string type: same as above
      "string/quotedMobile": {
        type: "value",
        filter: (token) => token.$type === "string",
        transform: (token) => {
          const raw = token.original?.$value ?? token.$value ?? token.value;
          return `"${String(raw)}"`;
        },
      },

      // mode-stripping name transforms for mobile platforms (M1).
      // In dual-mode tokens.json, theme-aware tokens live at
      // `…modes.dark.$value` / `…modes.light.$value`. Mobile platforms
      // (Swift/Kotlin/Dart/Android XML) currently materialize **only the dark
      // mode** as canonical hex (M1 limitation — future M2 ticket adds light
      // variants). The light-mode tokens are filtered out per platform.
      //
      // For mobile, the dark tokens' generated names would include the noisy
      // `Modes.Dark` suffix unless stripped. The transforms below remove the
      // `modes` and `{mode}` path segments before applying case conversion,
      // so e.g. path `["global","color","bg","modes","dark"]` → `GlobalColorBg`
      // (pascal) / `globalColorBg` (camel) / `global_color_bg` (snake).
      //
      // For CSS, no stripping transform is needed — the symmetric custom
      // format computes variable names from the canonical (mode-stripped)
      // path directly.
      "name/pascal-stripped": {
        type: "name",
        transform: (token, { prefix }) => {
          const stripped = token.path.filter((seg, i) => {
            if (seg === "modes") return false;
            if (i > 0 && token.path[i - 1] === "modes") return false;
            return true;
          });
          return [prefix, ...stripped]
            .filter(Boolean)
            .map((s) =>
              s
                .split(/[-_\s]/)
                .map((w) => w.charAt(0).toUpperCase() + w.slice(1))
                .join("")
            )
            .join("");
        },
      },
      "name/camel-stripped": {
        type: "name",
        transform: (token, { prefix }) => {
          const stripped = token.path.filter((seg, i) => {
            if (seg === "modes") return false;
            if (i > 0 && token.path[i - 1] === "modes") return false;
            return true;
          });
          return [prefix, ...stripped]
            .filter(Boolean)
            .map((s, idx) => {
              const parts = s.split(/[-_\s]/);
              return parts
                .map((w, j) =>
                  idx === 0 && j === 0
                    ? w.charAt(0).toLowerCase() + w.slice(1)
                    : w.charAt(0).toUpperCase() + w.slice(1)
                )
                .join("");
            })
            .join("");
        },
      },
      "name/snake-stripped": {
        type: "name",
        transform: (token, { prefix }) => {
          const stripped = token.path.filter((seg, i) => {
            if (seg === "modes") return false;
            if (i > 0 && token.path[i - 1] === "modes") return false;
            return true;
          });
          return [prefix, ...stripped]
            .filter(Boolean)
            .map((s) => s.replace(/-/g, "_").toLowerCase())
            .join("_");
        },
      },

      // shadow type: expand DTCG 2025.10 composite token to string literal
      // CSS uses built-in shadow/css/shorthand, but Swift/Kotlin/Dart
      // have no built-in equivalent, so we output as string literal.
      // Handles DTCG {value, unit} dimension objects and {colorSpace, components, alpha} color objects.
      "shadow/mobileLiteral": {
        type: "value",
        filter: (token) => token.$type === "shadow",
        transform: (token) => {
          const v = token.original?.$value ?? token.$value ?? token.value;
          if (typeof v === "object" && v !== null && !Array.isArray(v)) {
            const fmtDim = (d) =>
              typeof d === "object" && d !== null && "value" in d
                ? `${d.value}${d.unit}`
                : String(d);
            const fmtColor = (c) => {
              if (typeof c === "object" && c !== null && "components" in c) {
                const [r, g, b] = c.components;
                const a = c.alpha ?? 1;
                return `rgba(${Math.round(r * 255)}, ${Math.round(g * 255)}, ${Math.round(b * 255)}, ${a})`;
              }
              return String(c);
            };
            return `"offsetX: ${fmtDim(v.offsetX)}, offsetY: ${fmtDim(v.offsetY)}, blur: ${fmtDim(v.blur)}, spread: ${fmtDim(v.spread)}, color: ${fmtColor(v.color)}"`;
          }
          return `"${String(v)}"`;
        },
      },
    },
    formats: {
      // symmetric dual-mode CSS format (D1-a + D2).
      //
      // Input tokens.json structure (when dualMode):
      //   global.color.{name}.modes.dark.$value
      //   global.color.{name}.modes.light.$value
      //   semantic.{...}.modes.{dark|light}.$value (aliased)
      //   component.{...}.modes.{dark|light}.$value (color aliases only)
      //   global.spacing.*, global.typography.*, global.shadow.*, etc. (flat, mode-agnostic)
      //
      // Output CSS structure (D2 symmetric — neither mode is "primary at :root"):
      //   :root {
      //     /* mode-agnostic tokens (spacing / typography / shadow / etc.) */
      //   }
      //   :root[data-theme="light"] { /* light color tokens */ }
      //   :root[data-theme="dark"]  { /* dark color tokens */ }
      //   @media (prefers-color-scheme: light) {
      //     :root:not([data-theme]) { /* light color tokens (OS-pref fallback) */ }
      //   }
      //   @media (prefers-color-scheme: dark) {
      //     :root:not([data-theme]) { /* dark color tokens (OS-pref fallback) */ }
      //   }
      //
      // Variable naming: token path is canonicalized by (1) stripping the
      //   "modes.{dark|light}" pair, and (2) stripping the leading "global"
      //   segment and applying category aliases so the emitted CSS variable
      //   name matches the HTML contract used in
      //   screens/_shared/root-variables.css, screen HTML var(--*) refs, and
      //   docs/html-generation-rules.md. The aliases mirror the short-form
      //   prefixes the contract requires:
      //
      //     global.color.{name}                    → --color-{name}
      //     global.spacing.{name}                  → --sp-{name}
      //     global.spacing.touch-target            → --sp-touch          (special case)
      //     global.typography.font-family-{role}   → --font-{role}
      //     global.typography.font-size-{scale}    → --fs-{scale}
      //     global.typography.font-weight-{weight} → --fw-{weight}
      //     global.typography.line-height-{name}   → --lh-{name}
      //     global.typography.font-variant-numeric → --font-variant-numeric
      //     global.border-radius.{name}            → --radius-{name}
      //     global.shadow.{name}                   → --shadow-{name}
      //
      //   The same `--color-bg` (etc.) appears in BOTH light + dark blocks
      //   with different values (mode-flipped, single variable name). No
      //   --foo-light variant.
      //
      //   Non-global tiers (component.*, semantic.*) currently still emit
      //   `--component-{...}` / `--semantic-{...}` and are not in the HTML
      //   contract; future tickets may rationalize those.
      //
      // Single-mode fallback: when no `modes.*` nodes exist anywhere in
      //   tokens.json, output a single `:root { ... }` block (identical to
      //   built-in css/variables — legacy projects unaffected).
      //
      // Style Dictionary v5 では hooks.formats[name] = format 関数を
      // 直接配置する (v5 API)。`{ name, format }` のオブジェクト形式は v5 で reject される。
      "css/variables-symmetric": function ({ dictionary }) {
          const allTokens = dictionary.allTokens;

          // Detect whether this token is mode-aware (path contains "modes.{dark|light}").
          // Returns { mode: "dark"|"light"|null, canonicalPath: string[] }.
          const analyzePath = (path) => {
            const idx = path.indexOf("modes");
            if (idx === -1 || idx === path.length - 1) {
              return { mode: null, canonicalPath: path };
            }
            const mode = path[idx + 1];
            if (mode !== "dark" && mode !== "light") {
              return { mode: null, canonicalPath: path };
            }
            const canonical = [...path.slice(0, idx), ...path.slice(idx + 2)];
            return { mode, canonicalPath: canonical };
          };

          // Style Dictionary's default `name` already joins t.path with "-".
          // We need names derived from the canonical (mode-stripped) path so
          // dark and light variants share the same CSS variable name.
          //
          // follow-up sweep (PR #73, follow-up to Copilot #1):
          // strip the leading "global" segment and apply category aliases so
          // the emitted name matches the HTML contract (--sp-*, --fs-*, etc.).
          // See the format comment block above for the full alias table.
          const canonicalName = (path) => {
            if (path.length < 2 || path[0] !== "global") {
              return path.join("-").toLowerCase();
            }
            const tier = path[1];
            const rest = path.slice(2);
            // typography is the only tier whose tokens.json keys carry the
            // sub-category baked into the leaf name (font-family-display,
            // font-size-base, font-weight-bold, line-height-base). All other
            // tiers (color/spacing/border-radius/shadow) have one extra path
            // segment we can rename directly.
            if (tier === "typography" && rest.length >= 1) {
              const leaf = rest[0];
              for (const [prefix, alias] of [
                ["font-family-", "font"],
                ["font-size-",   "fs"],
                ["font-weight-", "fw"],
                ["line-height-", "lh"],
              ]) {
                if (leaf.startsWith(prefix)) {
                  return [alias, leaf.slice(prefix.length), ...rest.slice(1)]
                    .join("-").toLowerCase();
                }
              }
              // typography.font-variant-numeric and other unaliased keys
              // pass through unchanged (no extra "typography-" prefix).
              return rest.join("-").toLowerCase();
            }
            const aliases = {
              "color":         "color",
              "spacing":       "sp",
              "border-radius": "radius",
              "shadow":        "shadow",
            };
            const alias = aliases[tier];
            if (alias === undefined) {
              // Unknown tier: fall back to "{tier}-{rest}" without the global
              // prefix (still better than --global-{tier}-{rest}).
              return [tier, ...rest].join("-").toLowerCase();
            }
            // Special case: spacing.touch-target → sp-touch (HTML contract).
            if (tier === "spacing" && rest[0] === "touch-target") {
              return [alias, "touch", ...rest.slice(1)].join("-").toLowerCase();
            }
            return [alias, ...rest].join("-").toLowerCase();
          };

          // Group tokens by canonical name → { agnostic?, dark?, light? }.
          const slots = new Map();
          for (const t of allTokens) {
            const value = t.$value ?? t.value;
            const { mode, canonicalPath } = analyzePath(t.path);
            const name = canonicalName(canonicalPath);
            if (!slots.has(name)) slots.set(name, {});
            const slot = slots.get(name);
            if (mode === null) {
              slot.agnostic = value;
            } else {
              slot[mode] = value;
            }
          }

          // Partition into mode-agnostic, dark, and light bucket arrays
          // (insertion-ordered for stable diffs).
          const agnostic = [];
          const dark = [];
          const light = [];
          for (const [name, slot] of slots) {
            if (slot.agnostic !== undefined) {
              agnostic.push(`  --${name}: ${slot.agnostic};`);
            }
            if (slot.dark !== undefined) {
              dark.push(`  --${name}: ${slot.dark};`);
            }
            if (slot.light !== undefined) {
              light.push(`  --${name}: ${slot.light};`);
            }
          }

          const hasThemed = dark.length > 0 || light.length > 0;
          const header = "/**\n * Do not edit directly, this file was auto-generated.\n */\n\n";

          // Single-mode (legacy): emit one :root block, identical to built-in.
          if (!hasThemed) {
            return header + ":root {\n" + agnostic.join("\n") + "\n}\n";
          }

          // Dual-mode: emit D2 symmetric 5-block structure.
          let out = header;
          if (agnostic.length > 0) {
            out += ":root {\n" + agnostic.join("\n") + "\n}\n\n";
          }
          // Explicit data-theme blocks (symmetric primary — neither mode is :root default).
          out += `:root[data-theme="light"] {\n` + light.join("\n") + "\n}\n\n";
          out += `:root[data-theme="dark"] {\n`  + dark.join("\n")  + "\n}\n\n";
          // OS-preference fallback (applies only when data-theme attribute is absent).
          const indent = (lines) => lines.map((l) => "  " + l).join("\n");
          out += `@media (prefers-color-scheme: light) {\n  :root:not([data-theme]) {\n` +
                 indent(light) + "\n  }\n}\n\n";
          out += `@media (prefers-color-scheme: dark) {\n  :root:not([data-theme]) {\n`  +
                 indent(dark)  + "\n  }\n}\n";
          return out;
      },
    },
  },
  platforms: {
    css: {
      transformGroup: "css",
      buildPath: "{build_path}/css/",
      files: [
        {
          destination: "variables.css",
          // symmetric dual-mode CSS format (D1-a + D2).
          // The custom format gracefully degrades to a single :root block when
          // tokens.json has no `modes.*` nodes (legacy single-mode projects unaffected).
          format: "css/variables-symmetric",
          options: { outputReferences: true },
        },
      ],
    },
    scss: {
      transformGroup: "scss",
      buildPath: "{build_path}/scss/",
      files: [
        {
          destination: "_variables.scss",
          format: "scss/variables",
        },
      ],
    },
    js: {
      transformGroup: "js",
      buildPath: "{build_path}/ts/",
      files: [
        { destination: "tokens.js", format: "javascript/es6" },
        { destination: "tokens.d.ts", format: "typescript/es6-declarations" },
      ],
    },
    // M1 limitation: mobile platforms (Swift / Android XML /
    // Compose / Flutter / KMP) currently materialize **only the dark mode** of
    // each theme-aware token (single hex per token, matching legacy
    // behavior). The `mobileDualFilter` below excludes `modes.light` tokens.
    // Mobile name transforms use the `*-stripped` variants to remove the
    // `modes.dark` noise from generated identifiers. A future M2 ticket will
    // add per-mode mobile output (e.g. `Colors.dark.bg` / `Colors.light.bg`).
    "ios-swift": {
      transforms: [
        "attribute/cti",
        "name/pascal-stripped",
        "color/UIColorSwift",
        "dimension/pxToNumber",
```

**dual-mode**: mobile name transforms use the `*-stripped` variants (`name/pascal-stripped` / `name/camel-stripped` / `name/snake-stripped`) which skip the `modes` and `{dark|light}` path segments. Mobile platforms also apply `mobileDualFilter` to keep only the dark slot of theme-aware tokens (M1 limitation — single hex per token, identical to 旧仕様 behavior). single-mode (legacy) projects are unaffected because the filter is no-op when no `modes` nodes exist.

### Step 3: Run Build

```bash
cd artifacts/{app_name}/build
npx style-dictionary build --config config.mjs
```

`npx` は Node の module resolution で `node_modules/.bin/style-dictionary` を上位ディレクトリに向かって探索する。`artifacts/{app_name}/build/` から見ると repo root の `node_modules/` が解決されるため、ad-hoc な `npm install` は不要。

**Expected output**: One `✔︎` line per generated file (count varies 2〜9 based on `platform_combo` + `mobile_framework` + `legacy_android_xml` — see Output table) with no warnings.

**If `style-dictionary: command not found`**: repo root で `npm ci` が実行されていない。`cd <repo-root> && npm ci` を 1 回実行してから再試行。

**If build fails**:
1. Read the error message carefully
2. Common errors:
   - `No tokens for {file}` → filter function doesn't match any tokens. Check `$type` values in tokens.json
   - `Token collisions found` → name transforms are not differentiating tokens. Verify `attribute/cti` is first in the transforms list
   - `Cannot resolve reference` → alias token references a non-existent path. Check `{global.color.primary}` format
3. Fix the issue in config.mjs or tokens.json and retry

**If warnings appear** (e.g., token collisions):
- This indicates the transforms list is missing or misconfigured
- Verify that `transformGroup` is NOT used for mobile platforms
- Verify `attribute/cti` is the first transform in each mobile platform

## Custom Transform Design Rationale

| Transform | Target $type | Reason |
|---|---|---|
| `dimension/pxToNumber` | dimension | Built-in `size/rem` → `remToCGFloat` chain multiplies DTCG px values by 16. Extract numeric value from px string instead |
| `fontFamily/quotedMobile` | fontFamily | Non-CSS platforms output without quotes, causing compile errors |
| `string/quotedMobile` | string | Same as above |
| `shadow/mobileLiteral` | shadow | No built-in composite shadow expansion for non-CSS platforms. Output as string literal |

## Design Decision: Why Not Use transformGroup for Mobile

In verification #2, combining `transformGroup` with `transforms` caused:
- Custom transforms interfering with built-in transforms
- Name transforms (`name/camel`) breaking, causing token name collisions
- Value transforms (`size/swift/remToCGFloat`) breaking, outputting raw strings

In verification #3, removing `transformGroup` for mobile platforms and explicitly listing all needed transforms in `transforms` resolved all issues.

## Known Limitations

- Shadow custom transform outputs string literals, not platform-native Shadow classes (`NSShadow`, `BoxShadow`, etc.). Extend the transform if native conversion is needed
- Dimension output is a plain number (`44`), without platform-specific wrappers like `CGFloat(44.00)` or `44.dp`. The format layer (`ios-swift/class.swift`, etc.) handles the wrapping
