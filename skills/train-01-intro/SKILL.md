# Step 01: イントロダクション

**磨く力**: ビジネス理解（の入口）

**役割の境界（内部方針・そのまま口に出さない）**: 本ステップの責務は「これから使う道具（ハンドブック）を
手渡し、オーナーの断片的な語りを受け取る」まで。シートの観点はハンドブックに書いてあるので、チャットで
説明し直さず、目を通すよう声をかけるだけにする。埋める対話（質問して深掘りする）は次のステップ（ヒアリング）
で行う。ただしこれは進行の内部方針であって、訓練中のコンサルタントに「ここではやりません／深掘りしません／答え合わせしません」
と**できないことを強調して伝えない**（後述 §手順3d の前向きな促しで表現する）。📚AIファシリテーターは正解ファイルを一切開かない。

## 手順

1. **ハンドブックを開く（実操作・必須。narration で済ませない）＝ハンドブック初出** — 次を**実際に実行してから**進む:
   - a. `artifacts/{app_name}/session.json` を Read。`current_step` が `1`（Step00 が設定済み）であることを確認する
     （未設定なら `1` を書く）。
   - b. `skills/train-handbook/SKILL.md` の手順Aで **`active_form = null`・`current_step = 1`** としてハンドブックを
     生成（`guide.html` を Write）し、**手順A4 の open 判定に従って開く**（この会話で最初の open なので
     `handbook_opened` が `true` でない（未 set / false）場合に open し `true` を立てる。新会話再開時は Preamble が `handbook_opened: false` にリセットするため
     やはり1回開く）。current_step=1 を反映するので手順一覧は「イントロダクション」が「◀ いまここ」になり、
     フォームはまだ「← いまここ」強調を付けない（記入はステップ2）。
   - ※ narration で済ませず a→b を必ず実行する（Write / open を実際に呼ぶ）。開けない環境ではパス提示に degrade（手順A4）。

2. **ハンドブックへの送り出し＋区切り（実操作・必須。narration で済ませない）** — `session.json.transcription_mode` が
   **未 set のときだけ**実行する（set 済みなら本手順を丸ごとスキップして手順3 へ＝記入方法は既に選ばれており、
   ハンドブックの確認も前回済んでいるので二度聞かない）。次の a→b を**実際に**行う:
   - ※ **ハンドブックを開いた（手順1）ことをもって本手順を済んだ扱いにしない**。画面を出すのと、目を通すよう声を
     かけるのは別の仕事。ここを飛ばすと、学習者は説明を受けずに記入方法だけ選ばされることになる。
   - a. **通常のチャットメッセージ**を出す（**長文を `AskUserQuestion` の question 本文に詰めない**＝ダイアログ内は
     描画が崩れやすく可読性も悪いため。説明はチャット本文に置き、直後の AskUq は短い問いだけにする）。骨子:
     - 「ハンドブックを開きました。訓練で使うシートとレーダーはここにあります。まず目を通してください。」
     - **シートの各項目（B1-B4 / P1-P6）をチャットに列挙しない**（ハンドブックに載っている＝同じ説明を2箇所に置くと、
       片方が「もう伝わったから不要」と判断されて落ちる）。
     - **記入方法の案内**（同じメッセージの末尾に置く。**チャットでの説明の場はここだけ**——次の AskUq には
       **要旨レベル（ラベル＋20 字程度）以外を再掲しない**）:
       - ※ ハンドブック（§sec-usage「基本の流れ」）にも**常設の要旨**が 2 行ある。役割が違うので重複ではない
         ——**ハンドブック＝後から見返せる常設の要旨（推奨がどちらか・オート記入は非推奨で動作確認向け）／
         本案内＝選ぶ瞬間の開示（上記 4 点すべて）**。帰結の詳細は本案内と選択肢が持つ。
         **推奨がどちらかを両方から落とさない**
         （Jira 完了条件「推奨は自筆であることがハンドブック・案内文面から伝わる」）。
       - 「シートの記入方法は2つあります。」
       - 「**学習目的なら『自分で書く』がおすすめ**です。聞いた話を自分の言葉で振り分けること自体が訓練の中身だからです。」
       - 「**『オート記入』は動作を確認したいとき用**です。オーナーが話したことをそのまま転記し、**要約・整理は
         しません**。**この回は、シートの整理を振り返りの自己評価の材料にしません**。」
       - 「**途中では変更できません**。」
     - **全体で 200 字以内に収める**（phase「📚 の 1 発話は 200 字以内・一度に頼むことは 1 つ」）。頼むことは
       「ハンドブックを見て記入方法を選ぶ」の 1 つ。**選択の判断材料（推奨がどちらか・その理由・オート記入は
       動作確認用であること・要約しないこと・振り返りの材料にしないこと・変更不可）は削らない**（削ると次の AskUq が説明なしの選択になる＝本手順を置いた意味が消える）。
       枕・言い換え・具体例で嵩を増やさない。
   - b. 上記チャットに**続けて** `AskUserQuestion` を**1問だけ**出す（ステップ移行ゲートではなく“区切り”。
     **共通2択で統一**の規約はゲート専用なので本区切りには適用しない）。この1問が「ハンドブックを開いたので確認して
     ほしい」旨・「この後オーナーの話が始まる」予告・記入方法の選択を**兼ねる**（問いを分けると同じ場面で2回踏ませることになる）:
     - question（短く）: 「ブラウザでハンドブックを開いたので確認してください。この後、オーナーの話が始まります。
       シートの記入はどちらにしますか？」
     - 選択肢は**記入方法の2つだけ**（「先にハンドブックを見る」等は置かない＝ハンドブックは開いたままで後から
       いつでも見返せるため、選択肢に足す必要がない）:
       - 「自分で書く（おすすめ）」／description「聞いた話を自分でシートに書きます」→ `transcription_mode = "self"`
       - 「オート記入（動作確認用）」／description「私が転記します。この回は振り返りの材料にしません」
         → `transcription_mode = "assisted"`
       - description は**各 20 字程度の要旨**に留め、**強調記法（`**`）は使わない**（ダイアログでは記法が文字のまま
         見えることがある・phase「選択肢の label / description も短く保つ」）。詳しい説明は直前のチャット本文が持つ
         （上記 a）ので、ここは**要旨だけを再掲**する——ラベルの「動作確認用」と「振り返りの材料にしません」は
         位置づけと最大の帰結なので、短くしても**落とさない**（phase「選択時に帰結まで開示する」）。
     - **選ばれた値は AskUq の直後に `session.json` へ Read → merge → Write back する**（手順3c まで待たない＝
       この後で会話が切れても選択が消えない）。未 set のまま先へ進めない（以降の分岐判定が定まらない）。
     - どちらかが選ばれたら**そのまま手順3 へ**（選択が確認済み・開始の合図を兼ねる）。「まだ見ていない」等が
       自由入力で返ってきたら急かさず待ち、あらためて同じ問いを出す。

3. **オーナーに話してもらう（tool 作業を先に済ませ、発話は1メッセージで末尾に出す）** — 記入方法が選ばれたら
   （または既に set 済みで手順2 をスキップしたら）、次の順で行う（**relay を含む最終メッセージの前に tool 作業を全部片付ける**＝phase「🙎‍♂️ relay を含むメッセージは
   ターン最終出力にする」）:
   - a. **AI原企画者 subagent の起動** — Agent tool で `ayatori-train-persona`（`scenario_id`〔session.json〕/ `mode: "intro"`）。
     `intro_text` のみが返る（ground_truth の他フィールドは返さない契約）。
   - b. **dialogue-log への記録（必須・省略不可）** — `intro_text` を `artifacts/{app_name}/dialogue-log.md` に
     `🙎‍♂️ 担当者（オーナー）：` ラベル付きで**逐語**追記（無ければ新規作成）。イントロはステップ7 一次資料の起点であり、
     別会話再開時 main は intro_text を持たない（正解ファイルを開かない）ため、ここで記録し損ねると復元できない。
   - c. **セッション更新** — `session.json` を Read → `current_step` を保持しつつ `intro_completed_at` を追記 → Write back
     （`transcription_mode` は手順2 で既に書いてある）。
   - c2. **【オート記入のときだけ】イントロの語りを転記＋ハンドブック再生成** —
     `transcription_mode == "assisted"`（未 set / `self` なら本手順を丸ごとスキップ）のとき、`intro_text` のうち
     **B1-B4 / P1-P6** に当たる部分の**逐語**を、入れる欄を 📚 が判断して `understanding-notes.md` に清書し
     （`skills/train-handbook/SKILL.md` §B）、続けて手順A で再生成する。許容範囲（何を書いてよく何が禁止か）の正本は
     phase「チェックシートを編集するのは訓練中のコンサルタントだけ」節の例外。
     **relay より前に済ませる**（tool 作業は d の最終メッセージの前に片付ける）。
   - d. **最後に、オーナーの一連の発話を 1 メッセージでまとめて出す（後続 tool call なし）** — 案内ラベル＋オーナー発話＋
     整理の促しを**1つの最終メッセージ**として提示する（ハンドブックは開いているので言及しない）。
     **頼むのは「シートに整理する」の 1 つだけ**（phase「📚 の 1 発話は 200 字以内・一度に頼むことは 1 つ」）:
     ```
     📚AIファシリテーター：オーナーの担当者の方がいらっしゃいました。これからお話を共有します。

     🙎‍♂️ 担当者（オーナー）：{intro_text をそのまま逐語}

     📚 今の話を、ビジネス理解シート／プロダクト理解シートに整理してみましょう。全部埋まらなくて大丈夫です
     （空欄がこの後のヒアリングのチェックポイントになります）。ビジネス理解から先がおすすめです。
     ```
     - **ここで「オーナーに質問してみましょう」を併せて頼まない**（＝2 つ目の依頼になり、肝心の「シートに整理する」が
       埋もれる）。ヒアリングへの促しは、貼り戻しを清書した後に `skills/train-02-hearing` 手順4 が行う。貼り戻しが
       来ないまま学習者が質問を始めた場合はそのまま受け付ければよく（順序は強制しない）、手が止まっているときは
       train-02 §6c の迷子フォールバックで拾う。
     - 字数は 📚 部分だけを数える（relay の逐語部分は対象外）。
   - **【オート記入のときの差し替え】** — 上記の**整理の促し**（「シートに整理してみましょう」の段落）は出さず、
     c2 の転記結果を**欄の記号で報告**し、**フォームの扱い**を添え、**次の一手（オーナーへの質問）を頼む**。
     骨子（同じく 200 字以内・**頼むことは「オーナーに聞く」の 1 つ**）:
     > 「今の話のうち、シートに当たるところは私が写しました（**B1・B2・P1 に記載**／印は ✓ 事実）。**シートは
     >  基本的に触らなくて大丈夫です**。もし直したら、そのつど『コピー』で貼ってください。
     >  では、**気になったところをオーナーに聞いてみましょう**。」
     - **転記できる内容が無かった場合**は、報告の一文だけを差し替える（「今の話には、シートに写せるところは
       ありませんでした」）。**この差し替え自体をやめて自筆用の整理の促しに戻すことはしない**——オート記入は
       書かない前提の設定なので、ここで「シートに整理してみましょう」（＝フォームに書く指示）を出すと前提と
       逆を向く（phase「目標整理シートの空欄」の促さない方針）。**フォームの扱いの一文と質問の依頼は、この場合も出す**。
     - 「フォームの扱い」（触らなくてよい／直したら貼る）は**この回で必ず添える**（写せた内容の有無によらず
       ＝phase 例外の該当 bullet「無条件」）。ステップ2 でも同じ一文が重複して出ることは許容する（§train-02 手順2）。
     - **「質問を頼まない」制約は本差し替えには適用しない**: 自筆モードで質問を併せて頼まないのは、**依頼が 2 つに
       なって「シートに整理する」が埋もれる**ためだが、本差し替えには整理の依頼が無く**依頼枠が空いている**。
       ここで頼まないと、`skills/train-02-hearing` 手順4 の促しは**学習者の最初の質問入力を受けてからしか
       到達しない**（§train-02 手順4 の到達条件）ため、**学習者が自分で口を開くまで訓練が始まらない**。
     - 空欄を手がかりにしたその後の問いへの促しは、従来どおり `skills/train-02-hearing` 手順4 が続けて担う。
   - **禁止表現**: 「ここでは深掘りしません」「答え合わせはしません」等、できないことを強調する言い回しは使わない
     （同義・言い換え含め発想として出さない）。前向きな枠付け（「掘り下げて言葉になっていないことに気づけると理解が深まる」）は
     上記の促しに溶かしてよい。

4. **そのままヒアリングへ（移行ゲートは出さない）** — 手順3d の最終メッセージを出したら、`AskUserQuestion` の移行ゲートを
   挟まず、訓練中のコンサルタントの最初の質問入力を受けて **Step 02（ヒアリング）** に入る（ステップ1→2 はゲートを出さない・
   phase ステップ移行ゲート表）。
   - （「イントロをもう一度聞きたい」等の申し出があれば、そのとき intro_text を再提示する。）
