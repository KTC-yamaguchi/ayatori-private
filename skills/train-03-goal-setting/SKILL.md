# Step 03: 目標の認識合わせ

**磨く力**: 目標設定力（決める）

**役割**: ステップ2で引き出した断片を、訓練中のコンサルタントが「自分の言葉のゴール」にまとめ直す。これが AYATORI に
入れる前の最後の言語化（ステップ4＝AI伝達の直前）。📚AIファシリテーターは正解を持たず、採点しない。

## 前提

- ステップ2完了（`session.json.step2_completed_at` が set）。`understanding-notes.md` にビジネス理解／プロダクト
  理解シートが清書済み。

## 手順

1. **現在地の更新＋ハンドブックを開く（実操作・必須。narration で済ませない）** — 次を**実際に実行してから**進む:
   - a. `artifacts/{app_name}/session.json` を Read → `current_step` を **`3`** に更新 → Write back。
   - b. `skills/train-handbook/SKILL.md` の手順Aで `active_form = "goal"` としてハンドブックを**再生成（guide.html を Write）**。
        続けて**手順A4 の open 判定に従う**（初回のみ open・2回目以降は Write のみ＝タブに戻れば自動で最新。可否は
        `handbook_opened` が判定）。current_step=3 を反映するので手順一覧は「ステップ3」が「◀ いまここ」、目標整理シートが
        「← いまここ」で強調される。前ステップの表示が残らないよう、current_step と active_form を必ず今の値にしてから再生成する。
   - ※ narration で済ませず a→b を必ず実行する（Write を実際に呼ぶ）。訓練中のコンサルタントへは「ハンドブックを更新しました
     （開いているタブに戻れば最新です・閉じていたら開き直します）」と**一文で**述べる（✗「開き直しました」は使わない）。

2. **目標整理シートを訓練中のコンサルタント自身の言葉で書かせる** — 次を促す（**選択肢は出さず自由記述で受ける**）:
   - **G1 一言ゴール**: このプロジェクトが「成功」とはどういう状態か、一文で。**訓練中のコンサルタント自身が作文する**
     （オーナーの言葉の転記ではない・掴んだものを結晶化する）。
   - **G2 今回はやらないこと**: このPoCの枠（予算・期間）ではやらない／後回しにすること。
     **G2 を必ず書かせる**のが肝（不要機能や過剰要望を訓練中のコンサルタント自身が排除できるか）。
   - **目標整理シートに予算・制約の数字は書かせない**（だからシートに制約の項目は置かない）。精緻な内訳・算出根拠は
     オーナーからも出ない。ただし**オーナーに聞くこと自体は止めない** —— 大枠の枠感や「その枠でどこまで欲しいか」の
     優先順位・手応えは聞けば答えが返る（オーナー側の応答規約は `.claude/agents/ayatori-train-persona.md` §P3 が正本）。
     掴んだ枠感は G2「今回はやらないこと」の判断材料として使えば十分。
   - **📚 が G1/G2 の中身を代筆しない**（正本: phase「チェックシートを編集するのは訓練中のコンサルタントだけ」節・
     禁止例/可の線引きもそちら）。中身は訓練中のコンサルタントが書き、📚 は貼り戻しの逐語清書 → ハンドブック再生成に徹する。
     型名（型B/型D 等）を発話に出さない規約も phase「言い換え / 省略の規約」が正本。
   - **【オート記入（`session.json.transcription_mode == "assisted"`）のときは、上記の促しを出さず「スキップの説明」に
     差し替える】** — この設定は**動作確認用**（phase §例外の「位置づけ」）で、**書かない前提**の設定である。前提が
     そうなのに記入を促すと、前提（書かない）と設計（書いてください）が逆を向く——だから**この回は G1・G2 の記入を
     促さない**（本手順2 の促し・「学習目的ならおすすめ」の添え書きも出さない）。
     - なお **G1・G2 を 📚 が書くことは、この設定でも禁止**（転記の対象外＝phase 例外の「できないこと」）。促さない
       のは「学習者に頼まない」だけで、**代わりに 📚 が埋めるのではない**。この 2 つを混同しないこと。
       **📚 が「G2 は私が写します」と言ってはならない**（言うと学習者が任せて空欄になり、この訓練が丸ごと飛ぶ——
       自筆モードでの肝はそのまま生きている）。
     - **代わりに、何を飛ばしているかを説明する**（骨子・200 字以内・**頼むことは無い**）:
       > 「この回はオート記入なので、目標整理シートはスキップします。自分で書く回では、ここで**一言ゴール（G1）**を
       >  自分の言葉で作文し、**今回はやらないこと（G2）**を自分で決めます——掴んだ話を結晶化して、何を外すかを
       >  切るところが、このステップの中身です。」
       - **飛ばす事実と、飛ばしている中身の両方**を述べる（中身を言わずに飛ばすと、訓練の存在自体が伝わらない）。
       - 「代わりに書けません」等、**できないことを強調する言い回しは使わない**（phase §禁止表現）。
       - 学習者が**自分から書いた**場合は、通常どおり貼り戻しを清書する（手順3）——**書くのを止めはしない**。
     - 説明を出したら空欄のまま先へ進める（§手順6 の移行ゲート）。

3. **貼り戻しの清書** — 訓練中のコンサルタントがフォームの「コピー」でチャットに貼ったら、📚は `understanding-notes.md` に
   目標整理シートを清書する（`skills/train-handbook/SKILL.md` の清書手順・全文上書き）。

4. **オーナーとすり合わせる（確認は歓迎）** — 訓練中のコンサルタントが書いたゴールをオーナーに読み上げて
   「こういう理解で合っていますか？」と確認してよい（すり合わせはヒアリングそのもの・止めない）。
   - a. `dialogue-log.md` に訓練中のコンサルタントの確認を追記。
   - b. Agent tool で `ayatori-train-persona` を起動（`mode: "hearing_reply"` / `scenario_id`（session.json）/ `dialogue_log` 全文 /
     `user_utterance` ＝訓練中のコンサルタントの確認）。オーナーは「聞かれたことには語った範囲で正直に応える／未言及の核心は
     自分から出さない」ルールで応答する。
   - c. 応答を **先に** `dialogue-log.md` に追記する。
   - c2. **【オート記入（`assisted`）のときだけ】** すり合わせでオーナーが **B・P の訂正・補足**を述べた場合、
     その**逐語**を該当欄へ清書し（`skills/train-handbook/SKILL.md` §B）ハンドブックを再生成する
     （**relay より前に済ませる**）。**目標整理シート（G1・G2）は転記しない**（学習者が書く欄）。
     転記する内容が無ければ本手順はスキップ（報告もしない）。
   - d. **最後に** `🙎‍♂️ 担当者（オーナー）：` ラベル付きで提示する（**relay はターン最終出力にする**＝後続に tool call を
     作らない。記録 c ・転記 c2 は relay より前に済ませる。phase「🙎‍♂️ relay を含むメッセージはターン最終出力にする」参照）。
     - **【`assisted` のとき】** c2 で転記したら、この最終メッセージ内で relay の**後ろに**「B3 に記載しました」のように
       欄の記号で報告する（ファイル名は発話に出さない）。

5. **微修正** — すり合わせ結果を手がかりに、訓練中のコンサルタントが目標整理シートをフォームで微修正→貼り直し→📚清書。
   掘り足りない所があればステップ2に戻ってよい。

6. **移行ゲート（AskUserQuestion）** — phase「ステップ移行ゲート」に従い、**G1・G2 の両方が記入済み**に
   なったら**共通2択**を `AskUserQuestion` で出す（未記入のうちは出さず、記入を促す）。
   **オート記入（`assisted`）のときは、手順2 のスキップの説明を出した後は空欄のままでもゲートを出す**（説明の前には
   出さない＝何を飛ばしたか伝えずに飛ばさない。条件本体と理由は phase「目標整理シートの空欄」が SoT）:
   - 「次のステップに進む」
   - 「もう少し続ける（今のステップを続ける）」
   - 「進む」で完了扱い（下記）。「続ける」で本ステップに留まり目標を練る。
   - **辞退された後の再提示**は、**オーナーとの往復が 2 回以上進むか、学習者が貼り戻すか**のどちらかで行う
     （phase「ステップ移行ゲート」が SoT）。本ステップは**すり合わせ（手順4）が任意**で、誰にも聞かずに
     G1・G2 を書き続ける流れがふつうに起こるため、**往復だけを条件にすると再提示が永久に来ない**。
   - （「ヒアリングに戻って聞き直したい」等の申し出があれば、そのとき Step 02 を再開する。選択肢には出さない。）

## 完了後

- **完全な合意は要求しない**。「訓練中のコンサルタントが“決めた”ゴールが、オーナーの語った範囲と矛盾しない形でまとまった」ら次へ。
  一度も掘れなかった核心（型C の取りこぼし等）はステップ7 に残す（ここで先回りして明かさない）。
- 移行ゲート（手順6）で「進む」が選ばれたときに完了とする。
- `understanding-notes.md` に目標整理シートが確定保存済みであることを確認（**オート記入で空欄のまま進んだ場合は
  空欄のままでよい**＝書かせ直さない。§手順6）。
- `session.json` を Read → `step3_completed_at` を追記 → Write back
  （`current_step` は手順1で既に `3` に設定済み）。
- ステップ4（引き継ぎブリーフィング）へ進む。その後の AYATORI 入力（ステップ4本体）は素の本体パイプラインを
  訓練中のコンサルタントが別会話で実行する（B群）。
