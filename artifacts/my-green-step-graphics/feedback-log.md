- **[21b] Pattern C (パイプライン設計の欠落 — 透過の要否を上流で決めていない)**: グラフィックの背景を透過させるかどうかを 21b の箇所ヒアリング時点で user に確認しておらず、21d のプロンプト確定時に AI が placement 記述から推測して決めていた → 21g のレビューで user から「透過させる必要はない」と判明 → 5 枚の再生成が必要になった。**原因**: 透過は単なる見た目のオプションではなく **生成モデルと利用可能寸法を分岐させる上流制約** (透過 = 固定サイズ族 1024×1024 が上限 / 非透過 = 任意解像度)。21d で寸法を確定した後に透過を変えると、寸法の前提が崩れて全面再課金になる。**改善案**: `skills/21b-graphic-hearing/refs/hearing-guide.md` §5 の slot draft 項目に「透過の要否」を追加し、箇所選択と同じ人間ゲートで確定する (21d へ持ち越さない)。併せて 21b の提示文に「透過を選ぶと生成寸法が固定サイズ族に制限される」というコスト影響を明記する。
- **[21a] Pattern A (人間ゲート FB — 候補観点に「背景レイヤー」が無い)**: 21a はウェルカム画面に候補 #1 (ヒーロー領域のブランド画像) / #2 (価値3ポイントの 40px アイコンをイラストへ置換) を提示したが、user は両方を却下し「これらの部分を画像にするのではなく、画面全面の背景に画像を敷く方が綺麗になる。『自分の一歩が地球を変える』に合う背景グラフィックを、文字が見やすい前提で全面に入れたい」と判断した。**原因**: `skills/21a-graphic-recommend/refs/report-guide.md` §4 の候補観点が「既存アイコン位置の置き換え」と「既存 placeholder の直取り」に寄っており、**既存要素を持たない全面背景レイヤーという形の候補を構造的に出せない**。**改善案**: 候補観点に `full_bleed_background` (画面全面の背景レイヤー) を追加し、slot 種別の固定語彙にも加える。anchor 規約 (§7) は既存要素に紐付かないため、画面全体プレビューへ fail-open する扱いで足りる。
