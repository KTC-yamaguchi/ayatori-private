# 01 プロジェクト概要

## 1.1 目的

本プロジェクトは、個人の環境保護行動を支援するモバイルアプリケーション「MyGreenStep」を開発することを目的とする。ユーザーが日常生活で実践できるエコアクションを提案し、その効果をCO2削減量として可視化することで、「自分一人の行動でも環境に貢献できる」という実感を提供する。

## 1.2 背景

気候変動への関心が高まる一方で、多くの人が「自分一人が行動しても何も変わらない」という無力感を抱えている。環境問題に関する情報は溢れているが、個人レベルで「何をすればいいか」「その行動にどれだけの効果があるか」が分かりにくい状態にある。

この課題を解決するため、以下のアプローチを採用する。

- ユーザーのライフスタイルに合わせたパーソナライズされたアクション提案により、「何をすればいいか」の迷いを解消する。
- CO2削減量のビフォー・アフター可視化により、個人の行動が持つ意味をデータで証明する。

## 1.3 ターゲットユーザー

| 属性 | 内容 |
|------|------|
| ペルソナ | 環境問題に関心はあるが、具体的な行動に踏み出せていない一般生活者 |
| 年齢層 | 20代〜40代を主要ターゲットとする |
| ITリテラシー | スマートフォンの基本操作（アプリのインストール・利用）が可能なレベル |
| 動機 | 「何かしたいが、何をすればいいかわからない」「自分の行動に意味があるのか知りたい」 |

## 1.4 解決する課題

| 課題ID | 課題 | 本アプリによる解決策 |
|--------|------|----------------------|
| P-001 | 何をすればいいかわからない | 初回アンケートに基づくパーソナライズされたアクション提案 |
| P-002 | 自分一人の行動に意味がないと感じる | CO2削減量のビフォー・アフター可視化による効果の証明 |
| P-003 | 環境配慮行動が続かない | アクション記録と累積効果の可視化による継続動機の維持 |
| P-004 | 環境情報が専門的で取っつきにくい | 平易な言葉での説明と、具体的な行動ステップの提示 |

## 1.5 アプリの位置づけ

- **製品カテゴリ**: 個人向け環境保護支援アプリ（モバイル）
- **対応プラットフォーム**: iOS / Android（クロスプラットフォーム開発: Flutter / React Native / KMP のいずれか）
- **開発フェーズ**: MVP（最小限の実用可能な製品）
- **データ方針**: MVPでは一般的なCO2排出平均値を仮置きし、将来的に権威ある公的データソースに差し替える
- **認証方式**: メールアドレスによるアカウント登録

## 1.6 仮置き事項（正式確定が必要な項目）

以下の項目はMVP開発を進めるために暫定値・暫定方針を設定しているが、リリース前に正式な情報に基づいて確定する必要がある。

| ID | 仮置き項目 | 現在の状態 | 確定に必要なこと | 確定期限の目安 |
|---|---|---|---|---|
| TBD-001 | CO2削減量データ（ACT-001〜006） | 一般的な推計値を使用中 | 環境省「温室効果ガス排出量算定・報告マニュアル」等の公的データソースから正式な排出係数を取得し、数値を検証する | 開発フェーズ中盤まで |
| TBD-002 | CO2削減量データ（ACT-007〜009） | 概算の推計値のみ。算出根拠が他と比べて弱い | 窓の断熱効果・フードマイレージ・サプライチェーン排出に関する信頼できるデータソースを特定し、数値を算出する | 開発フェーズ中盤まで |
| TBD-003 | ベースライン算出の構成比 | 日本平均の概算値（電力50%、ガス15%、自動車20%等）を使用中 | 環境省「家庭部門のCO2排出実態統計調査」の最新版から正確な構成比を取得する | 開発フェーズ中盤まで |
| TBD-004 | ベースライン補正係数 | 再エネプランで電力分を0に補正、節水シャワーで×0.8等の概算値 | 補正係数の妥当性を専門家またはデータで検証する | 開発フェーズ中盤まで |
| TBD-005 | 開発期間・予算 | 未定（参考見積もり: 4ヶ月/800万円） | ステークホルダーとの合意 | 要件定義完了後すぐ |
| TBD-006 | クロスプラットフォームフレームワーク | Flutter / React Native / KMP のいずれか未選定 | 技術選定フェーズでNFR-P-01（コールドスタート3秒以内）の実機検証を実施して決定 | 設計フェーズ開始時 |
| TBD-007 | メール送信サービス | SendGrid等と記載。具体的なサービス・契約未確定 | サービス選定・契約・API設定 | 開発フェーズ序盤まで |

## 1.7 成功指標

| 指標ID | 指標 | 測定方法 | 目標値（MVP） |
|--------|------|----------|---------------|
| KPI-001 | アカウント登録完了率 | 登録開始数に対する登録完了数の割合 | 70%以上 |
| KPI-002 | 初回アンケート完了率 | 登録完了ユーザーのうちアンケートを完了した割合 | 80%以上 |
| KPI-003 | 週次アクティブユーザー率 | 登録ユーザーのうち週1回以上アクション記録を行った割合 | 30%以上 |
| KPI-004 | アクション記録頻度 | ユーザーあたりの月間アクション記録回数 | 月4回以上 |
| KPI-005 | 可視化画面閲覧率 | アクション記録後に可視化画面を閲覧した割合 | 60%以上 |
