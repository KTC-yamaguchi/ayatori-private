# 08 制約条件・受入基準

本ドキュメントは ISO/IEC/IEEE 29148:2018 に準拠し、MyGreenStep アプリの制約条件および受入基準を定義する。

---

## 8.1 開発制約

| ID | 制約 | 詳細 |
|----|------|------|
| CON-01 | クロスプラットフォーム開発 | iOS・Android を単一コードベースで開発する（Flutter または React Native） |
| CON-02 | MVP スコープ | 初回リリースは F-001〜F-009 の機能範囲に限定する。スコープ追加は次フェーズとする |
| CON-03 | 開発期間 | 未定。参考見積もり: デザイン1ヶ月→開発2.5ヶ月→テスト0.5ヶ月の計4ヶ月が余裕を持った目安（エンジニア2名＋デザイナー1名体制時）。確定後に本ドキュメントを更新する |
| CON-04 | 開発予算 | 未定。参考見積もり: 上記体制で約800万円が余裕を持った目安。確定後に本ドキュメントを更新する |
| CON-05 | CO2 データ | MVP では一般的な平均値（環境省公開データ等）を静的に使用する。個別精度の高い計算は次フェーズとする |
| CON-06 | 対応言語 | 日本語のみ（国際化対応は MVP 対象外） |
| CON-07 | 対応デバイス | スマートフォンのみ（タブレット・Web は MVP 対象外） |

---

## 8.2 前提条件

| ID | 前提 | 影響 |
|----|------|------|
| PRE-01 | ユーザーはインターネット接続環境を持つ | オフライン時は記録のローカル保存のみ対応 |
| PRE-02 | ユーザーはメールアドレスを持つ | ソーシャルログインは MVP 対象外 |
| PRE-03 | CO2 削減量の平均値は公開データに基づく | 数値の正確性は参考値レベルとする |
| PRE-04 | アプリストア（App Store / Google Play）での配信が可能 | 各ストアの審査基準に準拠する必要がある |
| PRE-05 | バックエンドはクラウド環境にデプロイする | AWS / GCP / Firebase 等（技術選定は設計フェーズで決定） |

## 8.3 受入基準（テスト可能な基準）

### 認証機能（F-001, F-002, F-009）

| ID | 基準 | 検証方法 |
|----|------|---------|
| AC-01 | 有効なメールアドレスとパスワード（8文字以上・英数字混在）で登録が完了する | 登録フォームに正しい値を入力し、確認メールが届くことを確認する |
| AC-02 | 登録済みメールアドレスでの重複登録時にエラーメッセージが表示される | 同一アドレスで 2 回登録を試行し、2 回目でエラーが表示されることを確認する |
| AC-03 | 正しい認証情報でログインが成功し、ホーム画面に遷移する | 登録済みアカウントでログインし、ホーム画面が表示されることを確認する |
| AC-04 | 誤ったパスワードで 5 回連続ログイン失敗後、15 分間アカウントがロックされる | 誤ったパスワードを 5 回入力し、6 回目でロックメッセージが表示されることを確認する |
| AC-05 | パスワードリセットメールのリンクから新しいパスワードを設定できる | リセット要求後、メール内リンクから新パスワードを設定し、ログインできることを確認する |

### アンケート（F-003）

| ID | 基準 | 検証方法 |
|----|------|---------|
| AC-06 | 初回ログイン後にアンケート画面が表示される | 新規登録後の初回ログインでアンケート画面への遷移を確認する |
| AC-07 | すべての質問に回答するとアクション提案画面に遷移する | 全質問に回答し、おすすめアクション一覧が表示されることを確認する |
| AC-08 | アンケート途中離脱後、再ログインで途中から再開できる | 途中でアプリを終了し、再ログイン後に未回答の質問から表示されることを確認する |

### アクション提案・記録（F-004, F-005, F-007）

| ID | 基準 | 検証方法 |
|----|------|---------|
| AC-09 | アンケート回答に基づいたアクションがホーム画面に表示される | 異なるアンケート回答パターンで提案内容が変わることを確認する |
| AC-10 | アクション詳細画面に名称・説明・CO2 削減目安が表示される | 任意のアクションを選択し、各項目の表示を確認する |
| AC-11 | 「実行した」ボタン押下後、完了アニメーションが表示され記録が保存される | ボタン押下後にアニメーション表示と、記録一覧への反映を確認する |
| AC-12 | オフライン時に記録した内容が、接続復旧後にサーバーに同期される | 機内モードで記録後、接続復旧でサーバーに反映されることを確認する |

### CO2 可視化（F-006）

| ID | 基準 | 検証方法 |
|----|------|---------|
| AC-13 | レポート画面に累計・週次・月次の CO2 削減量が数値とグラフで表示される | 複数のアクションを記録した後、レポート画面で各期間の数値を確認する |
| AC-14 | カテゴリ別の内訳が表示される | 異なるカテゴリのアクションを記録し、内訳表示を確認する |
| AC-15 | 記録 0 件の状態で適切な案内メッセージが表示される | 記録のないアカウントでレポート画面を表示し、案内メッセージを確認する |

### プロフィール（F-008）

| ID | 基準 | 検証方法 |
|----|------|---------|
| AC-16 | 表示名を変更して保存すると、次回表示時に反映されている | 表示名を変更・保存し、画面を再表示して反映を確認する |

## 8.4 リリース判定基準

| ID | 基準 | 判定条件 |
|----|------|---------|
| REL-01 | 受入基準の合格率 | 8.3 節の全受入基準のうち 100% が合格であること |
| REL-02 | 重大バグ | 致命的（アプリクラッシュ・データ損失）なバグが 0 件であること |
| REL-03 | 性能要件 | 06-non-functional.md の 6.1 節の全項目を満たすこと |
| REL-04 | セキュリティ | パスワードが平文で保存・送信されていないことを確認済みであること |
| REL-05 | 対応 OS での動作確認 | iOS 15・Android 10 の実機で主要フローが正常動作すること |
| REL-06 | ストア審査 | App Store・Google Play の審査ガイドラインに準拠していること |

## 8.5 既知のリスク

| ID | リスク | 影響度 | 発生可能性 | 対策 |
|----|-------|-------|-----------|------|
| RISK-01 | CO2 削減量の数値精度が低い | 中 | 高 | MVP では「参考値」と明示する。次フェーズで精度向上を図る |
| RISK-02 | iOS・Android 間の UI 表示差異 | 中 | 中 | 両 OS での実機テストを実施する。プラットフォーム固有の UI 調整を行う |
| RISK-03 | ユーザーのモチベーション維持が困難 | 高 | 中 | MVP リリース後にユーザーフィードバックを収集し、ゲーミフィケーション要素を次フェーズで検討する |
| RISK-04 | 開発期間・予算が未確定 | 高 | 高 | 早期にステークホルダーと合意する。スコープ調整の基準として、Must機能7件のうちF-004（提案エンジン）とF-006（可視化）を最優先とし、F-008（プロフィール編集）とF-009（パスワードリセット）は工数超過時に簡易実装に切り替え可能とする |
| RISK-05 | アプリストア審査でリジェクトされる | 中 | 低 | 審査ガイドラインを事前に確認し、プライバシーポリシー・利用規約を整備する |
| RISK-06 | 個人データの漏洩 | 高 | 低 | 暗号化・アクセス制御を徹底する。セキュリティレビューをリリース前に実施する |
| RISK-07 | クロスプラットフォームフレームワークの性能が非機能要件を満たさない | 中 | 中 | 技術選定フェーズでFlutter・React Native・KMPの3候補について、NFR-P-01（コールドスタート3秒以内）の実機検証を実施する。検証結果に基づきフレームワークを確定する |
| RISK-08 | CO2削減量データの差替時に既存記録との整合性が崩れる | 中 | 高 | ActionMasterにdata_versionフィールドを追加し、データ更新時にバージョンを記録する。既存のActionLogはログ作成時点のco2_reduction_kg値を保持し、遡及変更しない設計とする |
