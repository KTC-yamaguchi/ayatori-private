# 04 ユースケース定義

## UC-001: 新規アカウント登録

| 項目 | 内容 |
|------|------|
| UC番号 | UC-001 |
| アクター | 未登録ユーザー |
| 事前条件 | アプリがインストール済みであること。ユーザーがアカウントを持っていないこと |
| 基本フロー | 1. ユーザーが「新規登録」ボタンをタップする 2. システムが登録画面を表示する 3. ユーザーがメールアドレスとパスワードを入力する 4. ユーザーが「登録」ボタンをタップする 5. システムが入力内容を検証する 6. システムがアカウントを作成し、確認メールを送信する 7. ユーザーがメール内の確認リンクをタップする 8. システムがアカウントを有効化し、ログイン状態にする 9. システムが初回アンケート画面（UC-002）に遷移する |
| 代替フロー | 3a. メールアドレスが既に登録済みの場合: システムが「このメールアドレスは既に登録されています」と表示し、ログイン画面への導線を提示する。3b. パスワードが要件を満たさない場合: システムが「パスワードは8文字以上で英字と数字を含めてください」と表示する。7a. 確認リンクの有効期限（24時間）が切れている場合: システムが「リンクの有効期限が切れました。再送信しますか？」と表示する |
| 後条件 | ユーザーアカウントが有効状態で作成されている。ユーザーがログイン状態である |
| 関連機能ID | F-001, F-002, F-009 |

## UC-002: 初回アンケート回答

| 項目 | 内容 |
|------|------|
| UC番号 | UC-002 |
| アクター | 登録済みユーザー（アンケート未回答） |
| 事前条件 | ユーザーがログイン済みであること。初回アンケートが未回答であること |
| 基本フロー | 1. システムがアンケート画面を表示する（設問数と所要時間の目安を提示） 2. ユーザーが住居形態を選択する（戸建て／マンション／アパート） 3. ユーザーが居住人数を選択する（1人〜5人以上） 4. ユーザーが主な移動手段を選択する（自家用車／公共交通機関／自転車／徒歩） 5. ユーザーが通勤通学距離を選択する（2km未満／2-10km／10km以上） 6. ユーザーが食生活傾向を選択する（肉中心／バランス型／菜食寄り） 7. ユーザーが電力契約種別を選択する（一般／再エネプラン／不明） 8. ユーザーが環境配慮への関心度を選択する（低／中／高） 9. ユーザーが「回答を完了する」ボタンをタップする 10. システムが回答を保存し、アクション提案エンジンを実行する 11. システムが完了画面を表示し、おすすめアクション一覧への遷移ボタンを表示する |
| 代替フロー | 9a. 必須項目に未回答がある場合: システムが未回答の設問をハイライトし、「すべての設問に回答してください」と表示する。2-8a. ユーザーがアンケートを途中離脱した場合: システムが回答済み内容を一時保存し、次回ログイン時にアンケート再開を促す |
| 後条件 | アンケート回答がユーザープロフィールに保存されている。パーソナライズされたアクション提案リストが生成されている |
| 関連機能ID | F-003, F-004 |

## UC-003: おすすめアクションを確認する

| 項目 | 内容 |
|------|------|
| UC番号 | UC-003 |
| アクター | 登録済みユーザー（アンケート回答済み） |
| 事前条件 | ユーザーがログイン済みであること。初回アンケートが回答済みであること |
| 基本フロー | 1. ユーザーがホーム画面またはメニューから「おすすめアクション」をタップする 2. システムがパーソナライズされたアクション提案リストを表示する（アクション名、概要、期待削減量、難易度） 3. ユーザーが特定のアクションをタップする 4. システムがアクション詳細画面を表示する（実施手順、効果の根拠、当該ユーザーの期待削減量） 5. ユーザーが内容を確認する |
| 代替フロー | 2a. 提案可能なアクションが存在しない場合（すべて実行済みなど）: システムが「現在のライフスタイルに基づく提案はすべて確認済みです。アンケートを更新すると新しい提案が届くかもしれません」と表示する |
| 後条件 | ユーザーがアクション内容を理解し、実行判断ができる状態になっている |
| 関連機能ID | F-004, F-007 |

## UC-004: アクションを実行記録する

| 項目 | 内容 |
|------|------|
| UC番号 | UC-004 |
| アクター | 登録済みユーザー（アンケート回答済み） |
| 事前条件 | ユーザーがログイン済みであること。記録対象のアクションが提案リストに含まれていること |
| 基本フロー | 1. ユーザーがアクション詳細画面またはアクション一覧画面で「記録する」ボタンをタップする 2. システムが記録画面を表示する（実施日: デフォルトで当日、メモ欄） 3. ユーザーが実施日を確認または変更する 4. ユーザーが任意でメモを入力する（最大200文字） 5. ユーザーが「記録を保存」ボタンをタップする 6. システムが実行記録を保存する 7. システムが「記録しました！ 今回の削減量: X.X kg-CO2」と表示する 8. システムが累積削減量サマリーを更新表示する |
| 代替フロー | 6a. 同一アクション・同一日の記録が既に存在する場合: システムが「このアクションは本日すでに記録済みです」と表示する |
| 後条件 | アクション実行記録がデータベースに保存されている。累積CO2削減量が再計算されている |
| 関連機能ID | F-005, F-007 |

## UC-005: 自分の影響度を確認する

| 項目 | 内容 |
|------|------|
| UC番号 | UC-005 |
| アクター | 登録済みユーザー（アクション記録が1件以上存在する） |
| 事前条件 | ユーザーがログイン済みであること。アクション実行記録が1件以上存在すること |
| 基本フロー | 1. ユーザーがホーム画面またはメニューから「わたしの影響度」をタップする 2. システムがビフォー・アフター比較を表示する（アクション実行前の推定CO2排出量 vs 現在の推定CO2排出量） 3. システムが期間別CO2削減量推移グラフを表示する（デフォルト: 月次） 4. システムが累積削減量の数値を表示する 5. ユーザーが表示期間を切り替える（週次／月次／累積） 6. システムが選択された期間のデータに表示を更新する |
| 代替フロー | 1a. アクション記録が存在しない場合: システムが「まだ記録がありません。アクションを実行して記録してみましょう！」と表示し、おすすめアクション一覧への導線を提示する |
| 後条件 | ユーザーが自身のCO2削減効果を視覚的に把握できている |
| 関連機能ID | F-006 |

## UC-006: アンケートを再回答してアクション提案を更新する

| 項目 | 内容 |
|------|------|
| UC番号 | UC-006 |
| アクター | 登録済みユーザー（アンケート回答済み） |
| 事前条件 | ユーザーがログイン済みであること。初回アンケートが回答済みであること |
| 基本フロー | 1. ユーザーがプロフィール画面から「ライフスタイルを更新する」をタップする 2. システムが現在の回答内容が入力済みの状態でアンケート画面を表示する 3. ユーザーが変更したい項目を修正する 4. ユーザーが「更新する」ボタンをタップする 5. システムが更新内容を検証する 6. システムがアンケート回答を上書き保存する 7. システムがアクション提案エンジンを再実行する 8. システムが「ライフスタイル情報を更新しました。新しいおすすめアクションを確認しましょう」と表示する 9. システムが更新されたアクション提案リスト画面に遷移する |
| 代替フロー | 4a. 変更がない場合: システムが「変更はありませんでした」と表示し、プロフィール画面に戻る |
| 後条件 | アンケート回答が最新のライフスタイルに更新されている。アクション提案リストが新しい回答に基づいて再生成されている |
| 関連機能ID | F-003, F-004, F-008 |
