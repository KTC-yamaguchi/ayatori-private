# 08. 制約・受け入れ条件（Constraints & Acceptance Criteria）

## 開発制約

| ID | 制約 | 詳細 |
|---|---|---|
| **C-01** | スケジュール | PoC フェーズ: 4 週間（必要に応じて延長可） |
| **C-02** | 予算 | 未決定（フレキシブル） |
| **C-03** | チーム構成 | 1 名のエンジニア（フルスタック想定）+ デザイナー支援 |
| **C-04** | インフラ | v1 ではサーバーレス基盤（AWS Lambda / Vercel 等）を検討 |
| **C-05** | 技術スタック | 確定待ち（Step 5 で決定予定。React / Vue 等の選定） |

---

## 前提条件

| ID | 前提 | 説明 |
|---|---|---|
| **P-01** | 外部 API 利用可能 | 記事データを提供する API サービスが利用可能な状態 |
| **P-02** | ネットワーク接続 | ユーザーはネットワーク環境を前提（v1 ではオフライン非対応） |
| **P-03** | モダンブラウザ | IE11 は対象外。Chrome / Safari / Firefox の最新版を対象 |
| **P-04** | HTTPS 対応 | デプロイサーバーが HTTPS に対応（本番環境） |
| **P-05** | DNS レコード | 本番環境のドメイン名が決定・登録されている |

## 受け入れ条件（Acceptance Criteria）

### AC-01: ホーム画面にカテゴリ一覧が表示される

**前提:** アプリが起動され、ホーム画面がロード完了

**条件:**
- [ ] 少なくとも 3 つ以上のカテゴリが表示される
- [ ] 各カテゴリに アイコン・名前・説明が表示される
- [ ] カテゴリのタップ / クリックで、該当カテゴリの記事一覧に遷移する

**期待結果:** ユーザーが直感的にカテゴリを選択できる

---

### AC-02: カテゴリ別記事一覧が表示される

**前提:** ユーザーがカテゴリを選択

**条件:**
- [ ] 選択したカテゴリの記事が一覧で表示される
- [ ] 各記事にタイトル・著者・公開日・サムネイルが表示される
- [ ] 記事をクリック / タップすると、詳細ページに遷移する
- [ ] 記事一覧がスクロール可能（ページネーション または 無限スクロール）

**期待結果:** ユーザーが同一カテゴリ内の記事を複数閲覧できる

---

### AC-03: 記事詳細ページが表示される

**前提:** ユーザーが記事一覧から 1 件を選択

**条件:**
- [ ] 記事のタイトル・著者・公開日が表示される
- [ ] 記事本文（テキスト + 画像）が表示される
- [ ] 記事出典（メディア名）が表示される
- [ ] 「戻る」ボタンで一覧に戻れる

**期待結果:** ユーザーが記事を完全に読むことができる

---

### AC-04: キーワード検索が動作する

**前提:** ホーム画面の検索ボックスが表示されている

**条件:**
- [ ] 検索ボックスにキーワードを入力できる
- [ ] 入力中にオートコンプリート候補が表示される
- [ ] 検索ボタン / Enter キーで検索が実行される
- [ ] 検索結果が一覧で表示される（ヒット数が 0 の場合はメッセージ表示）
- [ ] 検索結果から記事を選択できる

**期待結果:** ユーザーが目的の記事をキーワードで検索できる

---

### AC-05: レスポンシブデザインが機能する

**前提:** アプリが PC（1440px）と スマートフォン（390px）の両方で表示される

**条件:**
- [ ] デスクトップ版: 記事一覧が複数列レイアウト、本文が読みやすい幅に制限される
- [ ] スマートフォン版: 記事一覧が 1 列、本文がスマートフォン幅に最適化される
- [ ] どちらも横スクロール不要
- [ ] フォントサイズがそれぞれの画面に最適化される

**期待結果:** ユーザーが使用デバイスに関わらず快適に利用できる

---

### AC-06: エラーハンドリングが機能する

**前提:** 何らかのエラーが発生（API 接続失敗、ネットワーク遮断等）

**条件:**
- [ ] ユーザーに適切なエラーメッセージが表示される
- [ ] キャッシュがあればそれを表示する
- [ ] 「再試行」ボタンが提供される
- [ ] 予期しないエラーは「問題が発生しました」のジェネリックメッセージで処理される

**期待結果:** ユーザーが何が起きたのか理解でき、対応策が提示される

---

### AC-07: アクセシビリティが確保される

**前提:** キーボードのみまたはスクリーンリーダーを使用

**条件:**
- [ ] Tab キーで全ボタン・リンクがナビゲート可能
- [ ] フォーカス表示が明確（輪郭線が 3px 以上）
- [ ] スクリーンリーダーで見出し / リンク / フォーム要素が正確に読み上げられる
- [ ] コントラスト比が WCAG AA 基準以上（4.5:1 以上）

**期待結果:** 障害のあるユーザーも全機能が利用できる

---

### AC-08: 性能要件を満たす

**前提:** 4G ネットワーク（実測速度: 10 Mbps）でアプリを使用

**条件:**
- [ ] ホーム画面の初期ロードが 3 秒以内
- [ ] 記事一覧の表示が 2 秒以内（キャッシュ利用時）
- [ ] 検索結果の表示が 1.5 秒以内
- [ ] 記事詳細ページの読み込みが 2.5 秒以内

**期待結果:** ユーザーがストレスなく操作できる応答性

## リリース判定基準

| 判定項目 | 合格基準 |
|---|---|
| **機能完成度** | Must 2 機能（F-01, F-03）が AC-01〜AC-08 を全て満たす |
| **バグ率** | クリティカルバグ 0 件。高優先度バグ ≤ 3 件 |
| **パフォーマンス** | NFR-01〜NFR-06 を全て満たす |
| **アクセシビリティ** | WCAG 2.2 AA レベルで測定。自動チェック 100% 合格、手動チェック 90% 以上合格 |
| **セキュリティ** | OWASP Top 10 の既知脆弱性がないことを確認 |
| **テストカバレッジ** | ユニットテスト ≥ 70%、E2E テスト ≥ 主要フロー 100% |
