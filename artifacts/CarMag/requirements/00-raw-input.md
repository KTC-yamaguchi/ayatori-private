# ヒアリング記録 — CarMag

## Axis 1: Target User（ターゲット）

**質問:** このサイトを一番開きそうな人と、その場面はどれが一番近いですか？

**回答:** 車を持つオーナー

**詳細:** メンテナンス時期（タイヤ交換など）や季節の備えで困ったときに情報を探す人。

---

## Axis 2: Problem（課題）

**質問:** 今はこうした車の情報をどうやって探していて、何が一番困りますか？

**回答:** 検索しても情報がバラバラ

**詳細:** Google で検索すると、ブログや広告記事が混じり、信頼できる情報にたどり着きにくい。

---

## Axis 3: Features（機能）

**質問:** v1 で 1 つだけ完璧にするなら？ / v1 に入れたい機能は？

**回答:** 
- **Must**: カテゴリ別の記事一覧・閲覧 — {public_api: 車情報API/RSSフィード}
- **Should**: 記事のキーワード検索 — {public_api: 同上}

**詳細:** コア機能はカテゴリ分けされた記事を閲覧できること。次に欲しいのはキーワード検索。

---

## Axis 4: Competitors / Reference Apps（参考アプリ）

**質問:** 参考になりそうなサイト・アプリはありますか？

**回答:** 車メディア系（カーセンサー等）

**詳細:** 記事中心・カテゴリ導線で整理されているメディアサイトが参考イメージ。

---

## Axis 5: Constraints（制約）

**質問:** すでに決まっている制約はありますか？

**回答:** 特に制約はない（後で決める）

**詳細:** 締め切り・予算・技術スタックは未定。フレキシブルに進める。

---

## Axis 6: Platform（プラットフォーム）

**質問:** ターゲットは主にどこでこのサイトを使いますか？

**回答:** WEBサイト（PC + スマホ両対応）

**詳細:** ネイティブアプリではなく、ブラウザ閲覧。スマホユーザーが多いが、PC からのアクセスも対応したい。

---

## Axis 7: Design Output Scope（設計範囲）

### 7-a) Platform Combination（プラットフォーム）
**回答:** `mobile_and_web`（ただし実装は WEB のみ）

### 7-a2) Web Viewports
**回答:** `["desktop", "sm"]` — PC幅（1440px）+ スマホ幅（390px）の両方

### 7-b) Screen Coverage（網羅範囲）
**回答:** `must_only` — Must 機能のみ（最小範囲）

### 7-c) State Pattern（状態パターン）
**回答:** `default_only` — 通常状態のみ。追加の状態パターン（empty/loading/error）は不要。

### 7-d) Mobile Framework
**スキップ** — 7-a が実質 WEB のみのため不要

### 7-e) Dual Theme Mode（テーマ）
**回答:** `false` — 単一テーマ（ライト）のみ

### 7-f) Illustration Policy（ビジュアル）
**回答:** `pictogram` — 記号的なピクトグラム（ホーム・検索・カテゴリなど）
