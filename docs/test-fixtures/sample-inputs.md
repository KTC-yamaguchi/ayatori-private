# 01 質問エージェント — 想定回答サンプル

パイプラインを初めて動かす際の動作確認用。
`/ayatori-question` 実行時にこの回答例をそのまま入力すると、02〜05 でスコア 80 点以上を取ることを想定して設計されている。
※ 本ファイルは旧 6軸時点の想定回答。26 ステップ再編後は 7 軸目「デザイン出力範囲」が追加されているため、`/ayatori-question` 実行時は 7 軸目にも回答が必要（例: 「Web のみ、Must + Should まで」）。

---

## アプリ名

**テスト用タスク管理アプリ**

---

## 6軸の想定回答

### 軸1: ターゲットユーザー

> 「10〜20名規模のスタートアップのエンジニアチームです。
> フルリモートで働いており、Slack と GitHub を日常的に使っています。
> タスクの粒度が細かくて、スプリント単位で管理したいニーズがあります。」

---

### 軸2: 解決したい課題

> 「今は GitHub Issues と Notion を別々に使っていて、ステータスが両方でバラバラになっています。
> どこを見れば今何をやっているかわからなくて、毎朝スタンドアップで確認し直す手間があります。
> エンジニアとPMが同じ画面を見て話せる場所が欲しいです。」

---

### 軸3: 主要機能（MoSCoW）

**Must（必須）:**
- タスクの作成・編集・削除（タイトル・説明・担当者・期日・ステータス）
- カンバンボード表示（Todo / In Progress / Done の3列）
- チームメンバーへのタスクアサイン

**Should（重要）:**
- ラベル・タグによるフィルタリング
- 期日アラート（期日3日前に通知）

**Could（あれば良い）:**
- GitHub Issues との連携
- スプリント・マイルストーン管理

---

### 軸4: 競合・参考アプリ

> 「Linear が一番近いです。シンプルで速い UI が好きです。
> Jira は機能が多すぎて使いにくい印象があります。
> モバイルはあまり使わない想定なので、Web メインで大丈夫です。」

---

### 軸5: 制約条件

> 「開発期間は 2 ヶ月の PoC です。
> 予算は特に決まっていないですが、外部 API の課金は最小限にしたいです。
> 技術スタックは Next.js + TypeScript + Supabase を想定しています。
> チームは 2 名のエンジニアで開発します。」

---

### 軸6: 対応プラットフォーム

> 「Web のみです。モバイル対応は今回スコープ外にしたいです。
> ブラウザは Chrome 最新版を想定しています。」

---

## Confluence 保存先

→ `confluence_parent_id = null` で設定する。
